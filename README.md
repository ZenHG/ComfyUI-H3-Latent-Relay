# ComfyUI-H3-Relay-Kit

MiniMax-H3 多段续接的 **latent 桥**（零重编码）—— 一个可独立使用、**零第三方节点包依赖**的 ComfyUI 节点包。
（只依赖 ComfyUI 自带的 `torch` 与 `safetensors`；不与任何第三方 H3 节点包耦合。）

> **怎么读**：前六节是**用法**（安装 → 5 分钟跑通 → 节点 → 接线 → 参数 → 排障）；
> 分隔线以下是 **🧠 原理与机制**（为什么这么设计、踩过哪些坑、判据证据）——**不看也能把片子跑出来**。

## 它解决什么问题

H3 分段生成时，"续接"要回答一件事：**新的一段怎么知道上一段结束在什么状态？**

主流做法是**像素续接**：把上一段的 mp4 解码成帧 → VAE 重编码成 latent → 当锚塞进条件。
问题在于：

- 多一次 VAE 往返，**有量化损失**；
- 重编码的 latent 与采样时那份**不是同一个东西**，锚点会漂移；
- 只能锚一个整块，位置固定在第 0 帧。

本包做的是**latent 桥**：直接从上一段的 AV latent 里切出尾段，切成逐 token 的块，
按真实位置写进 `minimax_keyframes`。**不重编码**，锚点与采样同源。

## 🚀 安装（2 分钟）

### 方式一：git clone（推荐）

```bash
cd ComfyUI/custom_nodes
git clone https://github.com/ZenHG/ComfyUI-H3-Relay-Kit.git
```

### 方式二：下载 ZIP

在仓库页面点 **Code → Download ZIP**，解压后把文件夹改名为
`ComfyUI-H3-Relay-Kit`，放进 `ComfyUI/custom_nodes/` 下。

装好后**重启 ComfyUI 后端**（装了 ComfyUI-Manager 就点 *Restart*；没装就重启 Python 进程）——
仅刷新浏览器不会加载新节点。节点列表里搜 `🔗 H3 续接` 即可看到本包的全部节点。

随包还带 **`examples/`**：一份可以直接打开的**最小演示工作流**
（`minimal_relay_official.json`，全官方节点 + 本包）和它的生成器脚本 ——
见 [`examples/README.md`](examples/README.md)。

**依赖**：只用 `torch` 与 `safetensors`（ComfyUI 自带；清单见 `requirements.txt`，
正常安装无需额外 `pip install`）。其中 **`torch` 是模块顶层 import**——缺少它整包注册失败、
节点列表里一个都看不到；`safetensors` 是延迟 import，缺了只在落盘那一步报错。

**宿主版本要求**：本包硬依赖**带 MiniMax-H3 支持的 ComfyUI**（需要
`comfy_extras/nodes_minimax_h3.py` 与消费 `minimax_keyframes`/`minimax_refs` 的
`comfy/model_base.py`）。装到不含 H3 的旧版 ComfyUI 上，节点能注册但续接静默无效——
用前先确认 ComfyUI 已更新到支持 MiniMax-H3 的版本。

**不依赖任何第三方 H3 节点包**：所用的 `minimax_keyframes` / `minimax_refs` /
`resolved_frame_index` 全是 ComfyUI **原生**协议，零 monkey patch。

## 🚀 5 分钟跑通（最小可用）

> 懒人路线：直接打开 `examples/minimal_relay_official.json`（全官方节点 + 本包，**18** 个节点，含一个画布注释框），
> 把 4 个加载器的下拉改成你本机的模型文件，然后按下面三步跑。
> 图的画布上有一个**注释框**写着同样的步骤，不用回来翻 README。

**第 1 段**

1. 把「① 段号」那个数字填成 `0`。
2. 在官方条件节点（`MiniMaxH3ImageToVideo` / `MiniMaxH3ReferenceToVideo`）里填好 prompt。
3. 点 Queue。

判据（日志里应看到）：

```
[H3 Relay] 无 context_latent → 直通（独立段，不续接）。
[H3 Relay] 裁 0 帧 → 不裁（独立段或纯首段）。
```

**第 2 段**

4. 把「① 段号」改成 `1` —— **只改这一个数**（桥和落盘都由它驱动，不用改第二处）。
5. prompt 换成第 2 段要拍的内容（开头直接接住上一段的动作/机位，别重新起手）。
6. 再点 Queue。

判据（三行，缺一不可）：

```
[H3 Relay] latent 桥续接：钉住 22 帧 / 7 步，锚位 0..18，裁首 23 帧（含沉降 1），音频 37 步
[H3 Relay] 裁首 23 帧 = 钉住 22 + 沉降 1 ｜ 自动检测：切换信号 203.0 / 基准 3.0（帧差突变/锐度塌陷/色档收敛）
[H3 Relay] 接缝自检：前 40 帧无突变（最大帧差 6.00，段内基线 3.00）→ 起点干净。
```

| 看到 | 说明 |
|---|---|
| `钉住 22 帧` | 上一段尾部**已接进来** |
| `裁首 N 帧 = 钉住 22 + 沉降 Y` | 接缝处理**已生效**（Y 由本段画面量出，逐段不同） |
| `起点干净` | 没有跳变，可以拼 |

> 示例走的是 **MotionContext 桥**（conditioning 路线，0.2.x 起即此接法）。0.4.0 起
> 还有**拷贝桥** `H3RelayCopyBridge`：把上一段尾 AV latent 逐位拷贝进本段初始
> latent + 噪声掩码，`mask_mode="hard"`（默认）时钉住区**不重绘**——复现发糊/漂移
> 这一类伪影从机制上消失。0.4.3 起新增 `mask_mode="ramp"`（噪声斜坡「软证据」档）：
> 掩码连续值按原生 H3 契约就是逐 token 的 sigma 标签，远端硬钉、缝端以 `ramp_top`
> 强度轻度 harmonize，全程每步仍被 (1-m) 锚回拷贝尾——治硬接缝处的色档/曝光台阶。
> ⚠️ `mask_mode="taper"` **不钉住**（掩码从头部 1.0 线性降到 `seam_min`，每帧留
> `seam_min`~100% 重绘自由度），是「渐进接管」对照实验档，别当默认用。
> 接法不同：它的输出接 KSampler 的 `latent_image`（不占 positive），见「节点」表
> 与 `CHANGES.md` 0.4.0 / 0.4.3。

**关键参数两张表**

| 参数 | 第 1 段 | 第 2 段起 | 在哪填 |
|---|---|---|---|
| 段号 `stage_index` | `0` | `1`、`2`、`3`… | 桥 + 落盘（**必须一样大**；示例图用同一个「段号」节点驱动，所以只改一处） |
| `run_id` | 同一个片子名，比如 `myfilm` | **与第 1 段一字不差** | 桥 + 落盘（两边一致） |
| `trim_frames` | `22` | `22`（不用动） | 桥（钉住窗口长度，只能 5/22/39/56/73/90/107/124） |
| `settle_frames` | —（首段不裁） | 保持 `0`（**不裁沉降**，不用管） | **裁重叠**节点 |
| `seam_ghost` | —（首段不裁） | 保持 `0`（默认关，不用管） | **裁重叠**节点 |
| `settle_sharpen` | —（首段不裁） | 保持 `0`（需要时再开） | **后处理 Post** 节点（裁重叠上还留着同名遗留档，见 Post 节 ⚠） |

**三个最常见的翻车点**

| 症状 | 原因 | 处置 |
|---|---|---|
| 日志写「静默直通」并直接报错 | 段号填了 ≥1，但 `run_id` 与上一段不一致，或上一段文件不在 | 两处 `run_id` 必须一字不差 |
| 画面从第 1 帧就开始重播上一段 | 「裁重叠」节点没接上，或它的 `trim_frames` 没接桥的**第 3 路输出** | 按下面接线图检查 |
| 换了新片子，结果接的是旧片的尾巴 | 没换 `run_id`（同名会覆盖/复读同段号文件） | 换新名字 |

## ✅ 默认够用 —— 先别调参

照上面三步跑完，就是这个包的**默认水平**：接缝起点干净、不跳帧、不重影，音频缝有上一段环境声打底。
**多数用户到此就够了。** 下面这些默认值**不是"待你优化的起点"，而是实测过的推荐值**：

| 旋钮 | 默认 | 为什么不建议动 |
|---|---|---|
| `trim_frames` | `22` | 钉住窗长度。实测**加长（22→39）不治糊、反而更差**（段头清晰度 0.864→0.805、缝处阶跃 0.0627→0.0732） |
| `settle_frames` | `0` | 不裁沉降。实测**裁沉降才是跳帧的来源**（裁 8 帧跳到 0.044、16 帧 0.055） |
| `seam_ghost` | `0` | 实测它只把一跳拆成两跳 |
| `mask_mode` | `hard` | 真续接。其余三档是**对照实验档**（见下） |
| Post 的画质旋钮 | 全 `0` | 全关 = **逐位直通**。它们是"补最后一点"，不是"必开" |
| 音频缝 `patch_seconds` | `0` | `0` = 直通；要用才开（且**第 1 段也要接** —— 它是后段的床源） |

> **🚫 实验档清单（别当默认）**：`mask_mode="taper"`（假拷贝，钉住区**没有被钉住**）、
> `mask_mode="ramp"`（copy 桥上实测与 `hard` **完全等同**：0.0407 vs 0.0402）、
> `mask_mode="blend"`、`match_prev=0.7`（实测把缝阶跃**放大 12.6 倍**）。
> 这些是留给我们自己做对照的，**产线默认一律不要开**。

**只有两种情况需要继续往下看**：

1. **画面细节/清晰度**不满意 → 先看下面「采样链」这一刀，再看「参数 → 续接后处理 Post」；
2. **缝上还剩极轻微的过渡**、想把最后 1% 也压掉 → 看「两条续接路线：怎么选」与「参数」。

### 🎛 采样链：两条路的取舍（通用说明，选哪条由你决定）

> 本包只处理 latent / AV 张量，**不含采样器**。下面不是"让你照抄我们的配置"，
> 而是**机制 + 实测**，帮你判断你自己那条链处在什么位置。

**先自查一件事**：打开你的采样器节点，看它是不是**渐进分辨率**（前期低分辨率、后期提升到全分辨率，
如 SelfLift 的 `transition_step` / `lowres_scale`），再看调度器**总步数** `N`。
如果是，那么**全分辨率上真正跑的步数 ≈ `N − transition_step`** —— 这个数就是细节的上限来源。
官方文档给的例子（8 步取 6）与你可能的默认（6 步取 4）**都只剩 2 步全分辨率**，这不是个别配置问题。

**为什么会"糊"（机制，不是调参失误）**：低分辨前缀的 latent **物理上没有高频**；
学习式提升只能"脑补"高频；剩下 2 步全分辨率远不足以补回来。
对比**全程全分辨率**的官方链（`SamplerCustomAdvanced` + euler），差别是**结构性的**。

**实测（同 seed、同提示词、同参考图、同参数，唯一变量 = 采样链；672×1184 / 90 帧 / 2 段）**：

| | **渐进分辨率链（SelfLift 类）** | **全程全分辨率（官方 `SamplerCustomAdvanced` + euler）** |
|---|---|---|
| 续段**细节**（全局高频中位） | 0.005750 | **0.011345（1.97×）** |
| 续段 1:1 局部细节 | 0.00604 | **0.01682（2.78×）** |
| 缝处亮度阶跃 | 0.0123 | **0.0094** |
| 缝区低频连续比（→1 = 连续） | 0.76 | **0.98** |
| 音频缝 `min_local/median`（去 priming 后） | **0.909** | 0.332 |
| 每段 NFE（去噪评估次数） | 相等（渐进分辨率**不增加** NFE） | 相等 |
| CFG | 可调（如 1.1） | **恒 1**（`BasicGuider` 无 negative 槽） |

**什么时候保留渐进分辨率链**：显存或时间受限；需要它的专属能力（切块省显存 / 高低分辨双模型 /
时域稳定补丁）；素材上**音频缝比画面细节更要紧**（本轮实测该链音频缝更好）。
**什么时候换全程全分辨率**：**画面细节优先**、显存能撑住 —— 这是"接缝无感"最直接的一步。

**若保留渐进分辨率，这几个参数决定细节与成本的分配**（参数名以 SelfLift 为例，同类实现语义相近）：

| 参数 | 作用 | 代价 |
|---|---|---|
| `transition_step` | 低分辨前缀的**步数**（= 便宜的步）；全分辨步数 = `总步数 − 它`。**降它 ⇒ 同样 NFE 下全分辨率占更多** | 全分辨步更贵（时间 ↑） |
| `rho` | `>0` 开启**锚点修正**（把高风险位置朝像素 VAE 锚点拉，治提升伪影）。官方 README 给 H3 的**建议起点**：`rho=0.6`、`w_min=w_max=1`。**本项目此前为 0，即该能力从未启用** | 多一次 VAE 解码→上采样→重编码往返 |
| `lowres_scale` | 低分辨前缀的**空间比例**（越大越细） | 算力 ↑ |
| `w_min` / `w_max` | 仅 `rho>0` 时生效的修正强度范围 | — |

> ⚠️ **诚实标注**：上表是**机制 + 官方文档**给出的方向，**我们尚未实测**（`rho` 一项尤其值得一试）。
> 测出来会写进 `CHANGES.md`，不吹不藏。

### 🧭 本包的设计取向：**该量的不让用户配，接缝无感是目标**

- **能智能量出来的，就不给旋钮**：裁多少帧由节点**当场测**（`trim_frames` 是"不许你配"的那一类）、
  沉降检测、音频床声窗位、电平对齐，都是运行时从你这段画面/音频里量出来的 ——
  因为这些是**客观可测量**的（见「裁多少帧：不让你配，由节点当场量」）。
- **只有"偏好 / 硬件"类才交给你**：镜像哪条链、要不要开画质域修复、掩码档位 ——
  这些取决于你的显存、素材与审美，**没有客观最优**，所以本包把它们放上画布并给推荐默认。
- **默认档就是"无感"档**：照「5 分钟跑通」跑，接缝处应当**看不出来**；
  还看得出来时，按上一节的顺序（先链、后画质域修复、最后掩码/裁量）逐级排查。

## 节点

**8 个节点分三层——但一个工作流只用得到前 3 个**（后 5 个都是"删掉照样跑"的可选项）：

| 层 | 节点 | 说明 |
|---|---|---|
| **必备 3** | Latent 存 · Latent 桥（或拷贝桥，二选一）· 裁重叠 | 少一个就不叫续接。示例图里也只有这 3 个是"必须接对"的 |
| **可选 3** | 后处理 Post · 音频缝 · 连跑 Chain | 各自独立、**默认全关 = 逐位直通**；不接它们行为与 0.4.x 一致。删掉不影响跑通 |
| **手动接线才用 1** | Latent 读 | 桥自己会从磁盘取源；只有要**显式换源**（`explicit_path`）时才手动接 |
| **另一种桥** | 拷贝桥 | 与 Latent 桥**二选一**，不是"多一个节点"，是"换一种接法" |

> 为什么不再合并？0.5.0 刚把 15 个后处理旋钮**从 `H3RelayTrimAV` 里拆出去**，理由就是
> "22 个 widget 的节点没法用"。再把不同域的旋钮合回一个节点（Post 19 个 + 音频缝 5 个 = 24 个）
> 等于把同一个教训重犯一次。**节点数不是复杂度，widget 数和"哪些线必须接对"才是。**

| 节点 | 作用 |
|---|---|
| 🔗 **H3 续接 Latent 存** | 本段采样后，把 AV latent 落盘到 `output/relay_kit/<run_id>/stage_NNNNN.safetensors` |
| 🔗 **H3 续接 Latent 读** | 读回上一段（段号 - 1），断点续跑时可指定 `explicit_path` 换源 |
| 🔗 **H3 续接 Latent 桥** | 上一段尾段钉进本段 conditioning；`context_latent` 不接则直通 |
| 🔗 **H3 续接 拷贝桥** | 上一段尾 AV latent **逐位拷贝**进本段初始 latent + 噪声掩码；`mask_mode="hard"`（默认）时钉住区不重绘，`ramp` 档缝端轻度 harmonize（软证据，0.4.3），`taper` 档不钉住（见参数表）；输出接采样器 `latent_image`（0.4.0 起，与 Latent 桥二选一） |
| 🔗 **H3 续接裁重叠** | **裁掉本段头部的重生成帧 + 自动裁掉紧随其后的「复现帧」（视频音频同裁）** —— 不裁就会在拼接处重播/跳变。第 4 路输出 `prev_tail` = **上一段末帧**，喂给下面的后处理节点 |
| 🔗 **H3 续接后处理 Post** | **画质域**后处理（不碰时间轴、不动帧数、不动音频）：跨段统计匹配 / 低频残差 / 段内直方图+白平衡 / 反卷积 / 段体高频迁移 / 糊区锐化。**全部默认关**；`guide` 接裁重叠的 `prev_tail` 才有"缝的另一侧"可对齐。**以后画质域新功能都加在这个节点上** |
| 🔗 **H3 续接音频缝** | **音频域**：把**上一段的环境声**补进本段头部，去掉裁切点上的解码静默（~32ms priming）与生成瞬态。**长度守恒**（音频采样点一个不增不减 ⇒ 零 A/V 位移），默认关。**以后音频域新功能都加在这个节点上** |
| 🔗 **H3 续接连跑 Chain** | 自动连跑控制器：同分组框内自动推进「桥 + 落盘」段号并排队（详见下方「Chain 自动连跑」） |

> **三个域，别混挂**：时间轴 = `H3RelayTrimAV`（冻结，不再长 widget）／画质域 = `H3RelayPost`／
> 音频域 = `H3RelayAudioSeam`。音频缝的落地**必须在节点里**——组装层（ffmpeg）那套
> crossfade / 补头 / 床环铺都是"渲染之后的第二步"，效果不落进段文件；节点版从段文件就带环境声。

## 接线

### 官方节点路线（推荐，`examples/minimal_relay_official.json` 就是这个）

```
UNETLoader ────────────── MODEL ─────────────┐
CLIPLoader ──── CLIP ─┐                      │
VAELoader(视频) ─ VAE ─┤                      │
VAELoader(音频) ─ VAE ─┤                      │
MiniMaxH3ImageToVideo ─┤                      │
  (= 官方出词节点，输出   │                      │
   positive + LATENT)   │                      │
   │                    │                      │
   ├─ positive ─────────┴→ 🔗 续接 Latent 桥 [0] conditioning ─┐
   ├─ LATENT ─────────────→ 🔗 续接 Latent 桥 [1] latent ─────┤
   │                       （[2] context_latent 留空，自动读）  │
   │                                                            │
   ├─ positive → ConditioningZeroOut ──────────────→ KSampler negative
   └─ LATENT ──────────────────────────────────────→ KSampler latent_image
                                                     KSampler positive ← 桥 [0]
```

### 🔧 节点在画布上为什么这么"小/大"——`advanced` 折叠（0.5.0）

本包节点**默认只把常用的几个旋钮画在画布上**，其余（细分参数与护栏）标了
`"advanced": True`，收进节点底部的展开区。这不是藏功能，是**为了节点别撑得那么大**：

- ComfyUI 前端的节点 resize 是**硬夹取**的：宽有 **225px 死下限**
  （`GraphView-*.js` 的 `useNodeResize` → `Math.max(size.width, 225)`），
  高也不能小于**内容高度**（widget 行数）⇒ **只有少渲染几行，节点才缩得下去**。
- `advanced` 是官方机制（`comfy_extras/nodes_model_advanced.py` 同款），
  **不改** widget 顺序、`widgets_values` 逐位取值、默认值，也不影响 API 提交。

想看到全部旋钮，三选一：
1. 点节点底部的 **advanced inputs** 展开条；
2. 右侧栏 → **Advanced Inputs** 分组（会列全所有节点的高级项）；
3. 设置里打开 **`Comfy.Node.AlwaysShowAdvancedWidgets`**（默认关 ⇒ 打开后全画布都展开）。

### 拷贝桥路线的接法差异

换 `H3RelayCopyBridge` 时，上面图里只有三处不同，其余（存 / 裁重叠 / Post / 音频缝）完全一样：

```
MiniMaxH3ImageToVideo ─ positive ────────────────→ KSampler positive（桥不占 conditioning）
                    └─ LATENT ─→ 🔗 续接 拷贝桥 [0] latent ─→ KSampler latent_image
                    （[1] context_latent 留空，桥自动读上一段）
                    桥 [2] trim_frames ─→ 🔗 续接裁重叠 [2]   ★和第 3 路一样必需
```

- 拷贝桥输出接 KSampler 的 `latent_image`（**不占 positive**）——这是它和 Latent 桥唯一的接线区别；
- 它同样有第 3 路 `trim_frames` 输出：**第 2 段起也要接到裁重叠**，否则钉住前缀原样留在成片里；
- 裁重叠 `settle_frames` 保持 `0`：拷贝桥不产生复现发糊，没有沉降可裁。

## 🔗 Chain 自动连跑

在图里放一个 `🔗 H3 续接连跑 Chain` 节点，把 **Chain + 桥 + 落盘** 三个节点
拉进同一个分组框（框选 → 右键 → 添加分组），按钮就长在 Chain 节点上：

| 按钮 | 干什么 |
|---|---|
| ▶ Run | 按当前段号跑一次（不满意再点一次，覆盖同段号文件） |
| ✔ Approve | 段号 +1（桥/落盘同步改），排队跑下一段 |
| ⏩ 连跑 | 按 segments 自动循环：跑完一段 → 段号+1 → 再跑（0 = 无限） |

## 参数

**续接 Latent 桥**

| 参数 | 默认 | 说明 |
|---|---|---|
| `trim_frames` | 22 | 钉住的像素帧数。合法值 5/22/39/56/73/90/107/124。22 是设计中心 |
| `audio_frames` | 0 | 音频钉住窗口（像素帧口径）。0 = 与视频同窗 |
| `context_latent` | — | 上一段 AV latent。不接 = 直通 |
| `anchor_latent` / `anchor_stage` | — / `-1` | **全局外观锚**（0.5.0）：长期钉进本段条件的身份基准段（通常是第 1 段）的 latent。`context` 管「接戏」，`anchor` 管「身份」（色档/光照/角色长相，永不退出）。不接锚 latent 但 `anchor_stage ≥ 0` 时自动读 `stage_<该值>` 落盘文件；`-1` = 关（行为与 0.4.x 一致）。治长片色档漂移（见「长片」一节） |
| `anchor_frames` | 5 | 锚窗帧数（同样只认 5+17k 网格）。5 = 一个 token，token 成本最低，身份/色档信息基本够用；锚块每步随采样骑乘，越大越贵 |

**续接 拷贝桥**（0.4.0，与 Latent 桥二选一）

| 参数 | 默认 | 说明 |
|---|---|---|
| `latent` | — | 本段初始 AV latent（接采样器上游） |
| `context_latent` | — | 上一段完整 AV latent（第 1 段不接本节点） |
| `context_frames` | 22 | 拷贝窗口帧数，合法值 5/22/39/56/73/90/107/124，须小于本段帧数 |
| `mask_mode` | `hard` | **掩码语义 = `模型生成 * m + 上段尾 * (1-m)`，m=0 才钉住、m=1 是重绘。**<br>`hard` = 全窗 m=0（钉住区零重绘，**真续接用这个**）；<br>`ramp`（0.4.3）= 噪声斜坡「软证据」：远端 m=0 硬钉 → 缝端**线性**升到 `ramp_top`，全程有锚（每步被 (1-m) 锚回拷贝尾）。原生 H3 契约把连续 m 当逐 token 的 sigma 标签（sigma_row = m·sigma_video），缝侧轻度 harmonize——治硬接缝处的色档/曝光台阶；<br>`blend`（0.5.0）= 重叠区**双向融合**：与 `ramp` 同语义，但权重用**窗形**升（两端导数为 0 ⇒ 过渡更柔，见 `blend_shape`）；<br>`taper` = 头部 m=1.0（**完全重绘**）线性降到缝端 `seam_min` —— ⚠ **钉住区实际上没有被钉住**，只作「渐进接管」对照实验档 |
| `blend_top` | 0.50 | 仅 `blend`：缝端**模型占比**上限（对应 ramp 的 `ramp_top`）。0 = 退化成 hard |
| `blend_tokens` | 0 | 仅 `blend`：参与融合的缝端 token 数；0 = 整窗铺开，小值（2~3）= 「只融缝、锁运动」 |
| `blend_shape` | `smoothstep` | 仅 `blend`：窗形。`smoothstep` = x²(3−2x) ／ `hann` = (1−cos πx)/2，**两者都是两端导数为 0 的单调升** |
| `taper_tokens` | 4 | 仅 taper：缝端前多少个 token 参与线性过渡 |
| `seam_min` | 0.10 | 仅 taper：缝端掩码下限（m 值）。`0` = 缝端完全硬锁；`0.3` = 缝端仍留 30% 重绘。**注意它只管缝端，头部恒为 1.0 全重绘** |
| `pin_audio` | `true` | 上一段音频尾拷进本段音频开头（采样上下文）。纯视频 latent 关掉它 |
| `ramp_top` | 0.25 | 仅 ramp：缝端最大 m（= 该 token 参与去噪的 sigma 比例）。`0` = 退化为 hard；`>0.5` 锚定明显变弱、接近 taper，慎用 |
| `ramp_tokens` | 0 | 仅 ramp：参与斜坡的缝端 token 数；`0` = 整个拷贝窗铺开；小值（2~3）=「只松缝、锁运动」的窄斜坡 |
| `anchor_latent` / `anchor_blend` | — / `1.0` | **色档纠偏锚**（0.5.0）：全局锚段（通常第 1 段）的 AV latent。接上后拷贝前缀的逐通道均值/方差被 Reinhard 矩匹配拉向锚段 ⇒ 每步钉回的就是已复位色档的上下文，本段新内容跟着回到全局色档。**纠偏只作用于被裁掉的钉住前缀，不碰上一段成片。** `anchor_blend` = 纠偏强度（1 全量对齐；锚段与本段有意的风格差异时调低；不接锚时无效） |

**续接裁重叠**

| 参数 | 默认 | 说明 |
|---|---|---|
| `images` | — | 本段解码后的全部画面（含头部重叠区） |
| `trim_frames` | 0 | 裁掉的**钉住区**帧数。**接桥的第 3 路输出即可自动同步**，不要手填 |
| `fps` | 24.0 | 帧率，用于把帧数换算成音频采样点 |
| `audio` | — | 本段音频。接了才与画面同裁，否则会音画不同步 |
| `settle_frames` | **0** | **0（0.5.0 起默认）= 不裁沉降** —— 实测「裁沉降」才是缝处跳帧的源头（裁 0 帧跳 0.020「几乎无感」／裁 8 帧 0.044／裁 16 帧 0.055），留下的是清晰度渐变、人眼容忍度极高；`-1` = 自动量出切换点并裁掉（**治糊但会引入跳帧**）；`N` = 固定多裁 N 帧 |

**第 4 路输出 `prev_tail`**（0.5.0 新增，追加在末位）：= 钉住区最后一帧 = **`images[pin-1]`**。
喂给 `🔗 续接后处理 Post` 的 `guide`，跨段项才有"缝的另一侧"可对齐。
⚠️ **它是否等于"上一段的末帧"，取决于走哪条桥**：**拷贝桥**下前 `pin` 帧是**逐位拷贝**的上段尾
⇒ `prev_tail` **就是**上段末帧；**Latent 桥**下前 `pin` 帧是**本段模型重画**的 ⇒ 只是个**近似**
（实测代理误差可达 0.006，比它要修的缝阶跃还大）。所以把 `guide` 当"精确参照"用之前，
先确认你在哪条桥上。

### 🔗 续接后处理 Post（0.5.0 新增）

| 参数 | 默认 | 说明 |
|---|---|---|
| `images` | — | **唯一必填**。接裁重叠的 `images`（裁后画面） |
| `guide` | — | 接裁重叠的 `prev_tail`（= 钉住区最后一帧 = 缝的另一侧）。**只有跨段两项需要它**；不接时那两项自动跳过。⚠️ **它是不是"上段末帧"取决于走哪条桥**：拷贝桥下**是**，Latent 桥（cond）下只是近似（见上节 `prev_tail` 的警告） |
| `match_prev` | 0 | **跨段统计匹配**：段头逐通道均值+标准差对齐 `guide`（Reinhard 式一阶+二阶矩）。**只对齐统计量、不复制姿态 ⇒ 无重影**。治成片缝上的亮度阶跃。⚠️ **实测建议：在 Latent 桥（cond）路线上保持 0**——该路线的缝本身已到 0.0007（可感阈值以下），而 `guide` 只是近似参照（见上节 `prev_tail` 的警告），对齐它会**把首帧推离真参照**（实测阶跃 0.0007 → 0.0039）；它真正的用武之地是**拷贝桥**（`prev_tail` 才是真参照） |
| `match_prev_frames` / `_gain_max` / `_offset_max` | 12 / 1.15 / 0.06 | 作用帧数（权重线性衰减到 0）／对比度增益护栏／偏移护栏 |
| `match_prev_stats_frames` | 1 | **统计量取几帧**——本条最容易写错。`1`（默认）= 只取**紧贴缝的那一帧**（与单帧 `guide` 同口径 ⇒ 修正量恰是"缝上的阶跃"，首帧被拉向 guide 而**不会越过**）；`0` = 旧口径（对整个作用区聚合）——段头**内部有亮度梯度**时会把首帧**推过** guide、缝上凭空多出一个阶跃（真渲染实测阶跃 ×12.6，**仅对照用**）；`>1` = 前 N 帧聚合 |
| `lowfreq_pull` / `_frames` / `_blur` | 0 / 12 / 64 | **低频残差传递**：只把段头**低频**色档对齐 `guide`。与 `match_prev` 的区别：本项只做低频**加性**（一阶）。⚠ 两者作用域重叠，建议二选一 |
| `head_zone_frames` | 24 | **组 2+3 共用的作用帧数**（从裁后首帧起）：下面「直方图 / 白平衡 / 反卷积 / 段体高频迁移」四项都按它作用（强度各自线性衰减到 0）。⚠ **只管组 2/3** —— 组 4 的「糊区锐化」用 `settle_sharpen_frames` |
| `hist_match` / `wb_match` | 0 / 0 | **段内**对齐（基准 = 本段段体）：直方图分布 / 灰世界白平衡（作用帧数见 `head_zone_frames`） |
| `deconv_strength` / `_radius` | 0 / 1.5 | 反卷积去模糊（Wiener），提升段头高频（作用帧数见 `head_zone_frames`） |
| `detail_borrow` / `_blur` | 0 / 9 | 段体高频迁移（把段头高频换成段体的结构）（作用帧数见 `head_zone_frames`） |
| `settle_sharpen` / `_frames` | 0 / 24 | 糊区锐化（unsharp，渐变）。**不裁、不动时间轴 ⇒ 不可能引入跳帧**。⚠ `_frames` 只管这一项 |
| `settle_auto` | 0 | **自适应糊区补偿（推荐替代上面的固定锐化）**：节点**当场量**每帧清晰度对段体基线的亏空（缝后第 2 帧最深、~15 帧爬回的爬升区），按亏空比例锐化——亏空越深补得越多；已达标的帧（含清晰的帧 0–1）与段体**逐位不动**。真实数据实测：SelfLift 快测档糊区最低 61% → 86%（strength=1.0）/ 99%（1.5）、锐度比 0.945 → 1.007/1.038、爬升 15 帧 → ~8 帧；官方链几乎无亏空 ⇒ 本项**正确地几乎不动**（无误伤）。⚠ 只能恢复对比度，救不回彻底丢失的细节 |
| `cross_seg_ack` | **False** | 🔴 **跨段两项的总闸**。不打勾（默认）⇒ `match_prev` / `lowfreq_pull` **不作用**（报告里说明原因）。**为什么默认关**：Latent 桥（cond）下 `prev_tail` 只是**近似**（代理误差 0.006 > 要修的缝阶跃 0.0007），实测对齐它反而把缝阶跃**放大 ×12.6** ⇒ 默认不让用户踩这个坑。确认 `guide` 是真参照（**拷贝桥**）才打勾 |
| `baseline` | `robust` | **组 2/组 3 的段体参考怎么取**。`robust`（默认）= 取段体**逐帧亮度中央 50%** 的帧做统计，并报**离散度** `(p75−p25)/中位`；离散度 > 0.08 ⇒ 组 2/组 3 **自动弃权**（宁可不动，也不用不可靠基准改画面）。`legacy` = 0.5.0 旧口径（整段均值，不筛不弃权），**仅作对照复现** |

**全部默认 0 ⇒ 逐位直通**（不接线时行为与 0.4.x 一致）。执行顺序：跨段色调对齐 → 段内色调对齐 → 补高频 → 锐化收口。

两条纪律（0.5.0 期实测逼出来的）：
1. **互斥组**：`hist_match` ↔ `wb_match`、`deconv_strength` ↔ `detail_borrow` **同时开只作用主项**（组 2 留直方图、组 3 留反卷积），次项弃权并写进报告 —— 叠加会让**后一层的基准失真、不可归因**。
2. **逐层可审计**：每层作用后报告里追加一行 `↳ 直方图匹配 后：段头亮度 0.24961→0.47531（+0.22569）｜高频 0.023201→0.035218（+51.8%）`，把「黑箱叠 N 层」变成「每层可归因」。

> `deconv_*` / `detail_*` / `settle_sharpen*` 在「裁重叠」节点上**还留着同名 widget**

### 🔗 续接音频缝（0.5.0 新增）

| 参数 | 默认 | 说明 |
|---|---|---|
| `audio` | — | **唯一必填**。接裁重叠的 `audio`（**第 1 段**没有裁重叠节点时，直接接音频解码 `VAEDecodeAudio`） |
| `run_id` / `stage_index` | `relay` / 0 | 与「续接桥 / Latent 存」**一字不差**；按段号顺序跑，别跳段 |
| `patch_seconds` | 0 | **头部补丁长度（秒）**。0 = 关（逐位直通）。要开先试 **0.2–1.2**：补丁区 = 上一段床声 + 电平对齐的渐入，盖住段首 priming 静默即可；过长会把本段自己的起拍/内容吃掉（实测 1.2s 曾把 BGM 起拍压平）。⚠ 必须先在**第 1 段**就接本节点（第 2 段的床源是它落盘的音频） |
| `bed_select` | `tail` | 床声选窗：`tail` = **上一段尾部同长窗**（紧邻缝、电平/音色与缝前天然连续——实测比"取全局最静"好 29 dB）；`quiet` = 0.5.0 旧行为（带下限选最静），仅对照复现。补丁还会做**电平对齐**（对齐缝前电平，±6 dB 限幅 + 0.995 峰值护栏） |
| `tile_seconds` | 0 | 床环铺瓦片长（秒）。0 = 整窗直取；前段干净窗短于 N 时用 1.2 |
| `fade_seconds` | 0.25 | 补丁边界（第 N 秒处）的交叉淡变宽度。0 = 硬切 |
| `bed_stage` | 0 | 用**第几段**的音频当床源。⚠ 必须 **< 本段段号**（床源得是已渲染完的段） |
| `join_*`（5 个，全折叠） | 见 tooltip | **第 3 路输出 `joined` 的拼接参数**：`join_curve`（等功率 `qsin`/线性 `tri`）、`join_prime_ms`（去编码器 priming）、`join_cross_ms`（交叉窗）、`join_segment_seconds`（每段音频有效时长 = 帧数/fps）、`join_align_seconds`（每缝画面裁量 = 裁帧数/fps）。`align>0` = **J-cut 时间轴守恒**：输出与裁后视频严格等长（实测对齐误差 0）、片尾无静音、跨段响度自动匹配（±6 dB 限幅）；`align=0` = 旧缩短语义（仅对照） |

**第 3 路输出 `joined`**：把链上各段音频拼成**整片一条音轨**（本节点输出，供封装/成片直接用）——
编码器给每段 mp4 头带来的 ~33 ms priming 静音在此被剔除，段间交叉用等功率曲线（不相关内容下
比线性淡变高 ~3 dB），是"缝上瞬时卡顿"的节点层修法。另落盘 `audio_raw_*`（原始未裁音频 =
J-cut 前奏素材源）与 `audio_joined.safetensors`（整片一条）。

**落盘**：每段都会写 `output/relay_kit/<run_id>/audio_NNNNN.safetensors`（与 latent 同目录，
`audio_` 前缀互不覆盖）——**第 1 段也必须接本节点**，第 2 段的床源就是它。

**守卫**（都明确报错，不静默）：床源段号 ≥ 本段 → raise；床源文件不存在 → raise 并提示先跑第几段；
`patch_seconds` 超出段长 → **夹到段长−1 并告警**（不炸整条链：一个环境声补丁不值得中断 30 分钟的渲染）。

**硬约束**：`context_latent` 与本段必须**同分辨率、同通道数**。
latent 无法缩放，不一致只能让上一段重跑或从本段重启链 —— 会明确报错。

## 排障

| 现象 | 原因 | 处置 |
|---|---|---|
| `不是 H3 的整步续接窗口` | 帧数不在 5+17k 上 | 改成合法值 |
| `context_latent 是 WxH，本段是 WxH` | 两段分辨率不同 | 统一分辨率重跑 |

## 🔧 工作流文件被改坏的自检（随包工具）

工作流的 `widgets_values` 是**按位置**对应前端 widget 槽位的。用脚本生成 UI 工作流时，
若漏掉 ComfyUI 前端**自动注入**的那一格（典型：带 `control_after_generate: True` 的 `seed`
后面会多一个下拉），其后所有取值会整体前移一位 —— 文件能打开、能提交，
但采样参数全错且**没有任何报错**（实测：`SelfLiftH3Sampler` 的
`w_max` 收到文件名、`upscaler_model` 收到 `false`）。

随包带一个体检脚本，拿真实 schema 逐位校验取值：

```bash
python tools/check_ui_workflow.py --all
python tools/check_ui_workflow.py /path/to/ComfyUI/user/default/workflows/xxx.json
```

**schema 来自两处**（2026-09-19 起）：**本包的 8 个节点现读包内 `nodes.py`**（代码才是权威），
其余节点才走正在运行的 ComfyUI 的 `/object_info`；顺带会把「服务端加载的定义与代码不一致」
报出来（提示该重启后端了）。**服务端连不上也不致命**：本包节点照样校验，只是非本包节点那部分标为「未查」。
ComfyUI 不在默认位置时用 `--comfyui /path/to/ComfyUI` 或环境变量 `COMFYUI_PATH`。
（判据：只看服务端的话，一个**还没重启的后端**会让它拿旧 schema 判新文件 ⇒ 误报或假绿。）

🔴 **动态 COMBO（如 `SaveVideo` 的 `format` / `codec`）也要查**：这类输入选中后会
**派生子 widget**（如 `format=auto` → `format.codec`），前端实际槽位是
`filename_prefix` / `format` / `format.codec` / `codec` 共 4 格。本包的生成器与体检器
都按 schema 的 `options[key].inputs` 把子参数展开，**不会**把动态 COMBO 当普通连线漏掉
——这是 2026-09-19 修过的自证式假绿重灾区（白名单漏一项、`want`/`got` 一起漏 ⇒ 错图也报 0）。
示例图 `examples/minimal_relay_official.json` 用当前版重新生成即可与前端存档逐位对齐。

## 🤖 API 提交（脚本 / 程序化）

本包 8 个节点**全部可经 `/prompt` API 提交**（与 UI 图同一套节点，无 UI-only 逻辑）。三条路：

1. **前端导出**：ComfyUI 菜单「工作流 → 导出（API）」得到 API 格式（每个节点是

2. **编程构造**：每个输入的名字/类型/默认值都可从 `GET /object_info` 查到
   （`oi["H3RelayPost"]["input"]["optional"]["settle_auto"]` 这样逐键读）——按名字填即可，
   连线值写 `[源节点id字符串, 输出序号]`。例：

   ```json
   "904": {"class_type": "H3RelayPost",
            "inputs": {"images": ["903", 0], "settle_auto": 1.0, "baseline": "robust"}}
   ```

3. **校验**：提交前跑 `python tools/check_ui_workflow.py 你的图.json`——本包节点用**本地定义**
   逐位校验（后端没重启也能查），取值错位/缺槽在这里现形。

⚠ 两个纪律：① `advanced: True` 的折叠参数**照常参与 API 提交**（折叠只是画布显示）；
② 改了节点参数名/顺序的版本升级，老 API 脚本要先对一遍 `object_info`（本包所有破坏性
变更都记录在 `CHANGES.md`）。

## 🧭 两条续接路线：怎么选（实测对比）

本包有**两个桥，二选一、不可同图串联**。它们**各有一个硬伤，没有一条白送**——按场景选：

| | **拷贝桥 `H3RelayCopyBridge`（`mask_mode="hard"`）** | **Latent 桥 `H3RelayMotionContext`** |
|---|---|---|
| 机制 | 上段尾 latent **逐位拷贝**，钉住区**零重绘** | 上段尾钉进 conditioning，模型**重画** |
| 发糊（复现沉降） | **无** | **有**（靠观测端沉降检测兜底） |
| 色档/亮度阶跃 | **大**（实测 0.040 ≈ 硬切级） | **小**（实测 0.004） |
| 要不要裁掉新内容 | **不要** | **要**（`settle_frames` 会吃新内容） |
| **内容 / 剧情风险** | **零** | **有**（段首有新内容时） |
| 适合 | **内容优先**：段首有台词/关键动作、一点内容都不想丢 | **平滑优先**：能接受段首一点糊，且能留出无台词缓冲 |

**一句话**：copy 换掉「发糊」，但买来「亮度硬跳」；cond 换掉「亮度硬跳」，但买来「发糊」。

> **想要第三条路**：`mask_mode="ramp"`（0.4.3 新增）——「软证据接缝」：每步仍锚回 `(1−m)`，
> `m` 从 0 缓升到 `ramp_top`（默认 0.25）。设计上可能同时缓解发糊与硬跳。
> **实测（2026-09-16，copy 桥）**：`ramp_top=0.25` 与 `hard` 在阶跃／锐度／运动余弦三项上
> **完全等同**（0.0407 vs 0.0402）——中间态没有出现 ⇒ **当前按对照档对待，别当默认用**。

切换方式见「节点」与「参数」两节；`settle_frames` 裁掉的是**新内容**这件事见
「接缝处的对话规避与音频处理」第 1 条的警告框。

## 与像素续接的关系

两者写的是**同一个 conditioning 协议**，因此可以互换：

| | 像素续接 | 本包（latent 桥） |
|---|---|---|
| 数据来源 | 上一段 mp4 → 解码帧 | 上一段 AV latent |
| VAE 往返 | 有（一次 encode） | **无** |
| keyframe 块数 | 1（整段锚 @frame0） | **逐 token 多块，按位置排** |
| 音频 | 挂在同一个 keyframe 上 | 走 `minimax_refs`，与视频独立窗口 |
| 逐位可复现 | 否 | **是** |

> 走本包时，上游节点（如 H3 导演台）的**像素续接字段必须留空**，
> 否则两套锚会同时写进 `minimax_keyframes`，画面互相打架。

## 时序网格（为什么只有特定帧数可用）

H3 VAE 的时序跨度为 `(1,4,4,4,4)`：每 5 个 latent token 覆盖 17 像素帧。
只有能**整步**切出的窗口才有意义：

```
合法窗口：5, 22, 39, 56, 73, 90, 107, 124 ...   （= 5 + 17k）
22 帧 =  7 个 latent token
39 帧 = 12 个 latent token
```

帧数不在网格上会渲染出**整体位移的接缝**，因此本包在越界时直接报错，
**不静默吸附到邻近值**。

另有一条硬约束：切出的尾段起点必须落在 5-token 周期边界，
否则各 token 的帧跨度与写入位置对不上 —— 同样会位移，同样报错。

## ⚠️ 为什么必须裁头

钉住区的前 `trim_frames` 帧并不是新内容 —— 它们是模型**对上一段尾部的重生成**
（实测逐帧 MAE ≈ 6/255，与"原帧"是同一画面的两次采样）。

实测证据：段 B 的首帧最相似的帧是段 A 的倒数第 22 帧（MAE 3.09），
而次优候选的 MAE 是 17.5 —— 孤立尖峰，说明匹配是真实的，不是巧合。

不裁的后果：**拼接处约 0.92 秒的画面重播**（22 帧 @24fps）。

裁的是 **decode 之后的像素帧，不是 latent** —— latent 的帧跨度由 token 在序列里的
相位（`k % 5`）决定，砍头会让相位错位。音频必须**同裁**，否则音画失步。

## 🔍 裁多少帧：不让你配，由节点当场量

**固定裁帧数不总对。** 实测（2026-09-11，低规格 448×768）：

| 段长 | 只裁钉住区（22 帧）后的首帧 | 说明 |
|---|---|---|
| **73 帧** | ❌ 有突变 | 切换点在**原第 22→23 帧之间**（MAE 6.52 → **102.27**），22 恰好把突变**前**那帧留在裁剪后第 0 帧 |
| **107 帧** | ✅ 干净 | 切换点更靠前，被完整裁掉 |

原因：模型在续接段开头会先复现上一段尾部（钉住区），**之后才切到按 prompt 生成**。
这个切换点落在哪一帧，取决于段长与 prompt —— 它是个**逐段不同**的量。

⇒ 所以它不该是让你填的配置，而是**当场量出来的量**：`H3RelayTrimAV` 收到的就是
完整解码画面，真实切换点此刻就在手上。默认 `settle_frames = 0`（**不裁沉降**，0.5.0 起）
时**一帧沉降都不裁**——实测「裁沉降」才是缝处跳帧的源头（实测数据见下方红框），
留下的只是**清晰度的渐变**，人眼容忍度极高。
想要旧的自动裁切：填 `-1`（会自动量出切换点并裁掉，但**会引入跳帧**）；填 `N` = 固定多裁 N 帧。

```
[H3 Relay] 裁首 23 帧 = 钉住 22 + 沉降 1 ｜ 自动检测：切换信号 203.0 / 基准 3.0（帧差突变/锐度塌陷/色档收敛）
           画面 73 → 50 帧（3.042s → 2.083s）；音频 97333 → 66666 采样点
[H3 Relay] 接缝自检：前 40 帧无突变（最大帧差 6.00，段内基线 3.00）→ 起点干净。
```

**默认什么都不用做。** 三种情况：

| 你想要 | 怎么设 `settle_frames` |
|---|---|
| 接缝**无跳**（默认） | 保持 `0` —— 只裁钉住区（上一段尾的复现，裁它不丢东西） |
| 段首更清晰（治糊） | 填 `-1`（自动量出该裁几帧）⚠ **代价：会引入跳帧** |
| 各段**等长** | 全片填同一个正数，例如 `9`（代价：每段成片短 9 帧） |

> 🔴 **为什么默认不裁沉降？** 实测（同一条段，只改裁量）：
> 裁 0 帧 → 缝处跳 **0.020**（几乎无感）／裁 8 帧 → 0.044／裁 16 帧 → 0.055（明显跳）。
> **「裁沉降」才是跳帧的源头**；留下的那几帧只是**清晰度的渐变**（先略糊、再恢复），
> 人眼对渐变的容忍度极高。⇒ 拿「可容忍的渐变」换「不可容忍的突变」不划算。

### 段首糊怎么办：`settle_sharpen`（糊区锐化，画质域修复）

**背景**：默认不裁沉降后，续接段开头会保留几帧「模型重绘导致的糊」。
时间轴两条路都不能走 —— **裁它 → 跳帧**；**不裁 → 留糊**。
⇒ 第三条路：**在画质域修** —— 不裁、不动时间轴，只提升糊区高频。
**因为完全不碰时间轴，所以从原理上不可能引入跳帧。**

`settle_sharpen` 对裁后**开头若干帧**做 unsharp mask，强度从缝端最强**线性衰减到 0**
（糊本身就是渐变的，强度也该渐变）；`settle_sharpen_frames` 控制作用帧数（默认 24 ≈ 1 秒）。

| `settle_sharpen` | 效果 |
|---|---|
| `0`（默认） | 关 |
| `0.4`–`1.0` | 推荐区间（先试 `0.6`，再目检有没有 halo / 噪点） |

**真实成片实测**（糊区首帧锐度 ÷ 段体基准）：

| amount | 相对基准 | 最大像素改动 |
|---|---|---|
| 0.00（原） | 0.873 | 0 |
| 0.60 | 0.953 | 0.091 |
| **1.00** | **1.008** | 0.151 |
| 1.50 | 1.080 | 0.227 |

> ⚠️ **诚实边界**：**锐化只能恢复「对比度」，不能恢复「已丢失的真实细节」。**
> 对「结构还在、只是软」的重绘糊有效；细节彻底丢了救不回来。
> 副作用是放大噪声、强边缘可能出白边（halo）→ `amount` 上限设 1.5。

### 缝帧重影 `seam_ghost`（**默认关**——实测它只把一跳拆成两跳）

裁掉沉降区是必要的（否则留下「先模糊再清晰」的尾巴），但**裁切本身就是时间跳跃**——
裁得越多、缝处跳得越大。裁 16 帧时实测跳帧达 **0.055**（肉眼可见的「跳一下」）。

**缝帧重影**把裁后**首帧**替换成「上段末帧 ⊕ 本段首帧」的加权混合（默认各 50%），
于是缝处的**一跳被拆成两个半跳跨两格**，一闪而过 → 体感约等于一镜到底。

| `seam_ghost` | 效果 |
|---|---|
| `0`（**默认**） | 关闭，回到硬接（缝处会看到一跳）—— 实测**这是观感最好的一档** |
| `1` | 1 帧重影。数值上跳帧 **0.055 → 0.029**（阈值 0.030 以下 = 「不跳」），但**观感更差**：总位移只减 7%、异常帧数 1→2（一跳变两跳 = 卡两下），且混合帧本身是个可见鬼影 |
| `2`–`6` | 更多帧重影（更长、更软的交叉溶；一般不需要） |

- **帧数守恒**（替换而非插入）⇒ **音频不用跟着动、不会有音画漂移**；
- **零采样开销**（纯张量后处理，不碰采样器、不额外渲染）；
- 代价：重影帧自身略软（实测锐度 0.41×，**仅 1 帧**）。

`seam_ghost_alpha` 控制上段末帧的权重（默认 `0.5` = 对半）。越小越偏本段首帧、重影越淡。

> **真实对照**（同 latent、同 seed、同裁量，唯一变量 = 重影开关）：
> 关：缝处帧差 `1.26 1.11 `**`14.08`**` 1.51` → 归一 0.055 ⛔
> 开：缝处帧差 `1.27 1.11 `**`7.22 7.51`**` 1.48` → 归一 0.029 ✅

判定口径：窗口紧贴钉住区（`pin-1 .. pin+12`），基线取自**钉住区内部**的相邻帧差中位数，
`帧差 > 4 × max(基线, 1.0)` 即认定为切换点；检出位置超出上限一律不动刀
（硬跳 / 色档路 12 帧；锐度塌陷路 36 帧——见上「段首缓冲」的 `settle_frames` 注）。
纯 CPU、只算需要的那一小段（每段约 40 ms），零额外依赖。

> **段内自己的切镜不会被误判。** 老实现扫「前 40 帧全局最大」，本段第 25 帧的真实切镜
> 会被当成接缝、并建议把新内容整段裁掉；现在窄窗根本看不到它。裁后自检也只在
> 位置足够靠前时才给"再裁 N 帧"的建议，否则只报位置不动刀。

## 🎬 接缝处的对话规避与音频处理（出词纪律 + 音频缝配套）

节点链把**画面**接缝处理干净（钉住 → 裁头 → 沉降），但接缝区还有两类坑
在**出词侧**和**音频侧**，三者是一套配合，缺一角就出伪音/断句：

### 1. 段首缓冲：续接段开头要留出「裁头 + 余量」

裁重叠会吃掉续接段头部 = **`trim_frames`（钉住区，默认 22 帧）+ `settle_frames`（沉降：0.5.0 起默认 `0` 不裁；开自动 `-1` 时按检测路上限分别是 12 帧（硬跳/色档路）/ 36 帧（锐度塌陷路））**。
**0.5.0 默认只裁 22**；最坏情形（自动沉降取满 36 帧）≈ **58 帧 ≈ 2.42s**（实测典型值：cond 桥 ≈ 38 帧 ≈ 1.58s）。对话排在这里会被**拦腰裁掉**（实测教训：台词起音被裁）。

⇒ 续接段开头 **≥ 裁头 + 0.2s 不排台词**（0.5.0 默认只裁钉住区 ⇒ ≥1.1s；若开了自动沉降 ⇒ ≥2.6s）；续接段的 `[Shot 1]` 只写画面与机位承接，
台词从后面的 Shot 起。**保守起见直接按第 2 条的 ≥3.6s 排，两条约束同时满足。**

> ⚠️ **`settle_frames` 裁的是「新内容」，不是重复内容——这是最容易踩的一条。**
> 裁切量 = `trim_frames + settle_frames`，但两笔账性质完全不同：
> - `trim_frames` = 上一段尾的**复现**（重复画面，上一段已经放过）→ **裁它不丢东西**；
> - `settle_frames` = **本段新生成的内容** → **裁它就会丢**。
>
> 所以**段首有台词 / 关键动作 / 不可丢内容的场景**，二选一：
> 1. 用**拷贝桥 `mask_mode="hard"`**（钉住区逐位拷贝、模型不重画 → **不产生复现发糊**
>    → **根本不需要沉降裁切**，内容零风险）；或
> 2. 把 **`settle_frames` 设为 `0`**（只裁钉住区，最安全），代价是段首可能留一点糊。
>
> 拿不准就先设 `0` 跑一段，看桥/裁节点的 `report` 里报的塌陷深度再决定要不要开自动。

### 2. 台词安全时刻公式

```text
续接段台词的 prompt 时刻 ≥ 实际沉降裁头 + 音频缝补丁 N(建议 2.0s) + 0.2s 余量
0.5.0 默认（settle=0）⇒ ≥2.2s；开自动沉降（−1，典型 ≈24 帧）⇒ ≥3.2s
实际建议一律排 3.6s —— 两种情形同时满足
```

由来：🔗 续接音频缝补的 room tone 头部补丁（见第 4 条）只保留本段音频 N 秒之后的部分，
prompt 时刻换算到段内时刻后必须落在保留区。出词校验若有「首切点 ≤3s」
之类的节奏规则，把**切点与台词解耦**：切点排 2.8s，台词挂在 3.6s 的 Shot 上。

### 3. 末帧锚链：段 N 的末帧状态在段 N+1 出词里逐字复写

接力点选在**镜头运动中途 / 动作未完成**处；段 N+1 的 `<Video 1>`（或等价的
末帧参照）逐字复写段 N 末帧：谁在什么位置、手停在哪里、镜头推到哪。
跨段"一镜到底"的观感是**出词纪律**撑起来的，节点只保证不重播不跳切。

### 4. 音频接缝：**节点**把上一段的环境声补进本段头

H3 每段独立生成音频，续接段头部有两件事叠在一起：

- **解码 priming**：段首约 32ms 近静默（实测 −72 dB）——裁重叠把它正好放到裁切点上
  ⇒ 成片缝处**先"抽一下"再起乐**（缝起 20ms 比缝前低 12–13 dB，听感即"静音一瞬"）；
- **生成重启瞬态**：0~1.4s（实测频谱 0-1s 中高频达环境声 10×、20-60Hz 达 6×，
  低频尾巴衰减到 ~1.4s 才回环境水平）。

🔗 **续接音频缝**用一条等长的替换治掉这两件：把本段头部 `patch_seconds` 秒换成
**上一段的最静窗环境声**（stationary 噪声，拼接不可闻），到第 N 秒处交叉淡变回本段
自身音频，**之后一个采样点都不动**。

| 参数 | 做什么 | 什么时候用 |
|---|---|---|
| `patch_seconds`（默认 0） | 后段头部 N 秒整段替换为**前段最静窗**（自动选窗避开台词尾） | 建议 2.0（盖过 1.4s 瞬态尾巴） |
| `tile_seconds`（默认 0） | 床源改取 W 秒瓦片**自叠化环铺**满 N | 前段干净环境窗比 N 短时（台词密），用 1.2 |
| `fade_seconds`（默认 0.25） | 补丁边界的交叉淡变宽度 | 0 = 硬切（有可闻接点） |

**为什么必须在节点里做，而不是组装层**（这是 0.5.0 的路线修正）：

1. **效果要落进段文件**。组装层的补丁是"渲染之后的第二步"——UI 里播放、逐段验收、
   交付中间产物看到的都还是没有补丁的音频；节点版从段文件出来就带环境声。
2. **组装层 crossfade 有 A/V 位移**。ffmpeg `acrossfade` 的语义是**裁掉后段的头部 X 秒**
   （交叉区消耗的是后段内容）⇒ 每条缝让缝之后的**音频相对画面提前 X 秒**。
   实测（2 段、X=0.25）：音乐峰从 8.75s 移到 8.50s，而总时长不变（尾部补平）——
   4 段链就是累计 0.75s 的 A/V 相对位移。**节点的 patch 是等长替换，零位移。**

> ⚠️ 真 crossfade（两段叠化）**做不到"单段内长度守恒"**：它要裁掉**上一段**的尾巴，
> 而单段节点只能改本段。所以 crossfade 仍归组装层（需要时），等长路线用本节点。

频带剖面判据（同算法在组装层做的 A/B 实测，口径一致）：补丁前缝区 60-250Hz 达环境声
**4×**（可闻"无理由伪音"）；补丁后 ≈**1.0×**（与全片环境声中位持平）。
宽带口径：**补丁后缝邻域最静点不再落在缝上**（旧配方 Δ = −26.4 dB → 补丁后 Δ = −1.1 dB）。

**段首纪律仍是前提**：补丁会把这 N 秒换成环境声，所以续接段**前 1.2s 不该有台词**
（见上一条「段首缓冲」公式）。

### 5. 长片：段数没有机制上限

stage 链（落盘/读回）按段号自续（本段段号 - 1 = 要读的段号），节点上限 9999 段；
每段 192 帧（8s）即可任意延长成片。**漂移累积**——色档/角色/锐度随接力次数衰减
（2 段实测缝亮度阶跃 0.0004，目检"几乎完美"；≥3 段未系统实测）——0.5.0 起有**外观锚**治理：
Latent 桥填 `anchor_stage=0`（或接 `anchor_latent`）、拷贝桥接 `anchor_latent`，
让每段都以第 1 段为身份基准，锚不随接力退出（见「参数」两张表）。≥3 段仍建议逐缝机检：

- 视频缝亮度阶跃 ≤0.008（0-1 口径；>0.03 即硬切级——无缝口径专用，
  分镜剧的正常切镜本来就在这一档）；
- 音频缝区 60-250Hz ≤ 全片环境声中位 1.5×（>2.5 为 FAIL，瞬态凸起案实测 2.7~4×）；
- 组装四断言：帧数守恒 / PTS 无洞 / DTS 递增 / A·VΔ。

> 产线配套的一键链与逐缝自动验收脚本（`chain_auto.sh` / `h3_chain_accept.py`）
> 在作者的生产线仓库，不在本包内；本包只负责把**每一段的接缝在生成侧做干净**。

## 🔊 音频窗对齐口径

`audio_frames` 换算到 40Hz 音频栅格时**向上拓宽**到最近整步（原来是四舍五入）：
音频窗是给模型"已播声音"的上下文，多带半步安全，截短半步可能丢节拍点。
拓宽行为会写进 report 注记。
