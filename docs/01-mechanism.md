## 🧭 两条续接路线：怎么选（实测对比）

本包 0.6.0 起只有**一个复合桥** `H3RelayCopyBridge`，它把两条钉法**并联**生效（`[0]` latent 逐位拷贝 + `[3]` conditioning 钉帧）。
下表里两条**钉法**在 0.5.x 之前分属两个桥、只能二选一；0.6.0 起合并进同一个复合桥，同图并联、各取所长——既**不发糊**又**亮度不硬跳**：

| | **复合桥 · `[0]` latent 拷贝（管运动）** | **复合桥 · `[3]` conditioning 钉帧（管取景）** |
|---|---|---|
| 机制 | 上段尾 latent **逐位拷贝**，钉住区**零重绘** | 上段尾钉进 conditioning，模型**重画** |
| 发糊（复现沉降） | **无** | **有**（靠观测端沉降检测兜底） |
| 色档/亮度阶跃 | **大**（实测 0.040 ≈ 硬切级） | **小**（实测 0.004） |
| 要不要裁掉新内容 | **不要** | **要**（`settle_frames` 会吃新内容） |
| **内容 / 剧情风险** | **零** | **有**（段首有新内容时） |
| 适合 | **内容优先**：段首有台词/关键动作、一点内容都不想丢 | **平滑优先**：能接受段首一点糊，且能留出无台词缓冲 |

**一句话**：复合桥并联两路 ⇒ 既吃「拷贝路线零发糊」又吃「钉帧路线低亮度跳」；单独走某一路（只接 `[0]` 或只接 `[3]`）则回到上表各自的取舍。

> **想要第三条路**：`mask_mode="ramp"`（0.4.3 新增）——「软证据接缝」：每步仍锚回 `(1−m)`，
> `m` 从 0 缓升到 `ramp_top`（默认 0.25）。设计上可能同时缓解发糊与硬跳。
> **实测（2026-09-16，copy 桥）**：`ramp_top=0.25` 与 `hard` 在阶跃／锐度／运动余弦三项上
> **完全等同**（0.0407 vs 0.0402）——中间态没有出现 ⇒ **当前按对照档对待，别当默认用**。

切换方式见「节点」与「参数」两节；`settle_frames` 裁掉的是**新内容**这件事见
「接缝处的对话规避与音频处理」第 1 条的警告框。

原生即支持任意位置的 keyframe 锚，本包不需要修改 ComfyUI。

## 与像素续接的关系

两者写的是**同一个 conditioning 协议**，因此可以互换：

| | 像素续接 | 本包（latent 桥） |
|---|---|---|
| 数据来源 | 上一段 mp4 → 解码帧 | 上一段 AV latent |
| VAE 往返 | 有（一次 encode） | **无** |
| keyframe 块数 | 1（整段锚 @frame0） | **逐 token 多块，按位置排** |
| 音频 | 挂在同一个 keyframe 上 | 走 `minimax_refs`，与视频独立窗口 |
| 逐位可复现 | 否 | **是** |

> 走本包时，上游节点（如 H3 导演台）的**像素续接字段必须留空**，
> 否则两套锚会同时写进 `minimax_keyframes`，画面互相打架。

## 时序网格（为什么只有特定帧数可用）

H3 VAE 的时序跨度为 `(1,4,4,4,4)`：每 5 个 latent token 覆盖 17 像素帧。
只有能**整步**切出的窗口才有意义：

```
合法窗口：5, 22, 39, 56, 73, 90, 107, 124 ...   （= 5 + 17k）
22 帧 =  7 个 latent token
39 帧 = 12 个 latent token
```

帧数不在网格上会渲染出**整体位移的接缝**，因此本包在越界时直接报错，
**不静默吸附到邻近值**。

另有一条硬约束：切出的尾段起点必须落在 5-token 周期边界，
否则各 token 的帧跨度与写入位置对不上 —— 同样会位移，同样报错。

## ⚠️ 为什么必须裁头

钉住区的前 `trim_frames` 帧并不是新内容 —— 它们是模型**对上一段尾部的重生成**
（实测逐帧 MAE ≈ 6/255，与"原帧"是同一画面的两次采样）。

实测证据：段 B 的首帧最相似的帧是段 A 的倒数第 22 帧（MAE 3.09），
而次优候选的 MAE 是 17.5 —— 孤立尖峰，说明匹配是真实的，不是巧合。

不裁的后果：**拼接处约 0.92 秒的画面重播**（22 帧 @24fps）。

裁的是 **decode 之后的像素帧，不是 latent** —— latent 的帧跨度由 token 在序列里的
相位（`k % 5`）决定，砍头会让相位错位。音频必须**同裁**，否则音画失步。

## 🔍 裁多少帧：不让你配，由节点当场量

**固定裁帧数不总对。** 实测（2026-09-11，低规格 448×768）：

| 段长 | 只裁钉住区（22 帧）后的首帧 | 说明 |
|---|---|---|
| **73 帧** | ❌ 有突变 | 切换点在**原第 22→23 帧之间**（MAE 6.52 → **102.27**），22 恰好把突变**前**那帧留在裁剪后第 0 帧 |
| **107 帧** | ✅ 干净 | 切换点更靠前，被完整裁掉 |

原因：模型在续接段开头会先复现上一段尾部（钉住区），**之后才切到按 prompt 生成**。
这个切换点落在哪一帧，取决于段长与 prompt —— 它是个**逐段不同**的量。

⇒ 所以它不该是让你填的配置，而是**当场量出来的量**：`H3RelayTrimAV` 收到的就是
完整解码画面，真实切换点此刻就在手上。默认 `settle_frames = 0`（**不裁沉降**，0.5.0 起）
时**一帧沉降都不裁**——实测「裁沉降」才是缝处跳帧的源头（实测数据见下方红框），
留下的只是**清晰度的渐变**，人眼容忍度极高。
想要旧的自动裁切：填 `-1`（会自动量出切换点并裁掉，但**会引入跳帧**）；填 `N` = 固定多裁 N 帧。

```
[H3 Relay] 裁首 23 帧 = 钉住 22 + 沉降 1 ｜ 自动检测：切换信号 203.0 / 基准 3.0（帧差突变/锐度塌陷/色档收敛）
           画面 73 → 50 帧（3.042s → 2.083s）；音频 97333 → 66666 采样点
[H3 Relay] 接缝自检：前 40 帧无突变（最大帧差 6.00，段内基线 3.00）→ 起点干净。
```

**默认什么都不用做。** 三种情况：

| 你想要 | 怎么设 `settle_frames` |
|---|---|
| 接缝**无跳**（默认） | 保持 `0` —— 只裁钉住区（上一段尾的复现，裁它不丢东西） |
| 段首更清晰（治糊） | 填 `-1`（自动量出该裁几帧）⚠ **代价：会引入跳帧** |
| 各段**等长** | 全片填同一个正数，例如 `9`（代价：每段成片短 9 帧） |

> 🔴 **为什么默认不裁沉降？** 实测（同一条段，只改裁量）：
> 裁 0 帧 → 缝处跳 **0.020**（几乎无感）／裁 8 帧 → 0.044／裁 16 帧 → 0.055（明显跳）。
> **「裁沉降」才是跳帧的源头**；留下的那几帧只是**清晰度的渐变**（先略糊、再恢复），
> 人眼对渐变的容忍度极高。⇒ 拿「可容忍的渐变」换「不可容忍的突变」不划算。

### 段首糊怎么办：`settle_sharpen`（糊区锐化，画质域修复）

**背景**：默认不裁沉降后，续接段开头会保留几帧「模型重绘导致的糊」。
时间轴两条路都不能走 —— **裁它 → 跳帧**；**不裁 → 留糊**。
⇒ 第三条路：**在画质域修** —— 不裁、不动时间轴，只提升糊区高频。
**因为完全不碰时间轴，所以从原理上不可能引入跳帧。**

`settle_sharpen` 对裁后**开头若干帧**做 unsharp mask，强度从缝端最强**线性衰减到 0**
（糊本身就是渐变的，强度也该渐变）；`settle_sharpen_frames` 控制作用帧数（默认 24 ≈ 1 秒）。

| `settle_sharpen` | 效果 |
|---|---|
| `0`（默认） | 关 |
| `0.4`–`1.0` | 推荐区间（先试 `0.6`，再目检有没有 halo / 噪点） |

**真实成片实测**（糊区首帧锐度 ÷ 段体基准）：

| amount | 相对基准 | 最大像素改动 |
|---|---|---|
| 0.00（原） | 0.873 | 0 |
| 0.60 | 0.953 | 0.091 |
| **1.00** | **1.008** | 0.151 |
| 1.50 | 1.080 | 0.227 |

> ⚠️ **诚实边界**：**锐化只能恢复「对比度」，不能恢复「已丢失的真实细节」。**
> 对「结构还在、只是软」的重绘糊有效；细节彻底丢了救不回来。
> 副作用是放大噪声、强边缘可能出白边（halo）→ `amount` 上限设 1.5。

### 缝帧重影 `seam_ghost`（**默认关**——实测它只把一跳拆成两跳）

裁掉沉降区是必要的（否则留下「先模糊再清晰」的尾巴），但**裁切本身就是时间跳跃**——
裁得越多、缝处跳得越大。裁 16 帧时实测跳帧达 **0.055**（肉眼可见的「跳一下」）。

**缝帧重影**把裁后**首帧**替换成「上段末帧 ⊕ 本段首帧」的加权混合（默认各 50%），
于是缝处的**一跳被拆成两个半跳跨两格**，一闪而过 → 体感约等于一镜到底。

| `seam_ghost` | 效果 |
|---|---|
| `0`（**默认**） | 关闭，回到硬接（缝处会看到一跳）—— 实测**这是观感最好的一档** |
| `1` | 1 帧重影。数值上跳帧 **0.055 → 0.029**（阈值 0.030 以下 = 「不跳」），但**观感更差**：总位移只减 7%、异常帧数 1→2（一跳变两跳 = 卡两下），且混合帧本身是个可见鬼影 |
| `2`–`6` | 更多帧重影（更长、更软的交叉溶；一般不需要） |

- **帧数守恒**（替换而非插入）⇒ **音频不用跟着动、不会有音画漂移**；
- **零采样开销**（纯张量后处理，不碰采样器、不额外渲染）；
- 代价：重影帧自身略软（实测锐度 0.41×，**仅 1 帧**）。

`seam_ghost_alpha` 控制上段末帧的权重（默认 `0.5` = 对半）。越小越偏本段首帧、重影越淡。

> **真实对照**（同 latent、同 seed、同裁量，唯一变量 = 重影开关）：
> 关：缝处帧差 `1.26 1.11 `**`14.08`**` 1.51` → 归一 0.055 ⛔
> 开：缝处帧差 `1.27 1.11 `**`7.22 7.51`**` 1.48` → 归一 0.029 ✅

判定口径：窗口紧贴钉住区（`pin-1 .. pin+12`），基线取自**钉住区内部**的相邻帧差中位数，
`帧差 > 4 × max(基线, 1.0)` 即认定为切换点；检出位置超出上限一律不动刀
（硬跳 / 色档路 12 帧；锐度塌陷路 36 帧——见上「段首缓冲」的 `settle_frames` 注）。
纯 CPU、只算需要的那一小段（每段约 40 ms），零额外依赖。

> **段内自己的切镜不会被误判。** 老实现扫「前 40 帧全局最大」，本段第 25 帧的真实切镜
> 会被当成接缝、并建议把新内容整段裁掉；现在窄窗根本看不到它。裁后自检也只在
> 位置足够靠前时才给"再裁 N 帧"的建议，否则只报位置不动刀。

## 🛡 运行时契约（时序网格护栏）

桥 / 裁节点每次执行前，把本包的时序网格常量 `FRAME_PER_TOKEN` 与 live ComfyUI 的
`comfy_extras/nodes_minimax_h3.py` 源码对照：一致才放行（进程内缓存只查一次）；
上游更新改了网格则**拒绝运行**并报出两边各是什么——宁可不跑，不出坏片子。

## 🔊 音频窗对齐口径

`audio_frames` 换算到 40Hz 音频栅格时**向上拓宽**到最近整步（原来是四舍五入）：
音频窗是给模型"已播声音"的上下文，多带半步安全，截短半步可能丢节拍点。
拓宽行为会写进 report 注记。
