## 参数

**续接 拷贝桥（复合桥）**（0.6.0 起**唯一桥**；0.4.0 起即提供拷贝路线，0.6.0 折叠进 conditioning 钉帧路线）

| 参数 | 默认 | 说明 |
|---|---|---|
| `latent` | — | 本段初始 AV latent（接采样器上游） |
| `context_latent` | — | 上一段完整 AV latent（第 1 段不接本节点） |
| `context_frames` | 22 | 拷贝窗口帧数，合法值 5/22/39/56/73/90/107/124，须小于本段帧数 |
| `mask_mode` | `hard` | **掩码语义 = `模型生成 * m + 上段尾 * (1-m)`，m=0 才钉住、m=1 是重绘。**<br>`hard` = 全窗 m=0（钉住区零重绘，**真续接用这个**）；<br>`ramp`（0.4.3）= 噪声斜坡「软证据」：远端 m=0 硬钉 → 缝端**线性**升到 `ramp_top`，全程有锚（每步被 (1-m) 锚回拷贝尾）。原生 H3 契约把连续 m 当逐 token 的 sigma 标签（sigma_row = m·sigma_video），缝侧轻度 harmonize——治硬接缝处的色档/曝光台阶；<br>`blend`（0.5.0）= 重叠区**双向融合**：与 `ramp` 同语义，但权重用**窗形**升（两端导数为 0 ⇒ 过渡更柔，见 `blend_shape`）；<br>`window`（0.6.0）= **对称窗**：两端低、中心高 —— 与 ramp/blend 的**本质差别**是**缝端回落到低位 ⇒ 缝端重新钉牢**。依据 VideoMerge(arXiv:2503.09926) 的正弦窗与 Diff-VF(arXiv:2608.05976) 的 WWS（「中心权重高、边界权重低」，消融证明去掉它 → **窗口边界突然跳跃**）；<br>`taper` = 头部 m=1.0（**完全重绘**）线性降到缝端 `seam_min` —— ⚠ **钉住区实际上没有被钉住**，只作「渐进接管」对照实验档。<br>⚠️ **一条已作废的旧结论**：曾写「ramp 与 hard 三项完全等同 ⇒ 无增益」——那是用**看不见跳帧的指标集**测的。改用含「缝后单帧尖峰 + 缝对构图相关」的判据重测后：**四个掩码档在缝处全都跳**，只是失败模式不同（hard 保取景但运动尖峰大；ramp/blend 运动平了但**取景被改写**）⇒ **单靠掩码调参治不好**，须配合「复合桥」（见下）|
| `blend_top` | 0.50 | 仅 `blend`：缝端**模型占比**上限（对应 ramp 的 `ramp_top`）。0 = 退化成 hard |
| `blend_tokens` | 0 | 仅 `blend`：参与融合的缝端 token 数；0 = 整窗铺开，小值（2~3）= 「只融缝、锁运动」 |
| `blend_shape` | `smoothstep` | 仅 `blend`：窗形。`smoothstep` = x²(3−2x) ／ `hann` = (1−cos πx)/2，**两者都是两端导数为 0 的单调升** |
| `taper_tokens` | 4 | 仅 taper：缝端前多少个 token 参与线性过渡 |
| `seam_min` | 0.10 | 仅 taper：缝端掩码下限（m 值）。`0` = 缝端完全硬锁；`0.3` = 缝端仍留 30% 重绘。**注意它只管缝端，头部恒为 1.0 全重绘** |
| `pin_audio` | `true` | 上一段音频尾拷进本段音频开头（采样上下文）。纯视频 latent 关掉它 |
| `ramp_top` | 0.25 | 仅 ramp：缝端最大 m（= 该 token 参与去噪的 sigma 比例）。`0` = 退化为 hard；`>0.5` 锚定明显变弱、接近 taper，慎用 |
| `ramp_tokens` | 0 | 仅 ramp：参与斜坡的缝端 token 数；`0` = 整个拷贝窗铺开；小值（2~3）=「只松缝、锁运动」的窄斜坡 |
| **`conditioning`**（0.6.0） | — | **复合桥开关**：接上 ⇒ 本节点**同时**在 conditioning 上追加钉帧（管**取景/构图**），与 latent 钉住窗（管**运动**）**并联生效**——两条路径改的是不同对象（latent vs conditioning），采样器两个入口分开 ⇒ 互不冲突。<br>**不接 = 只做拷贝桥，行为与 0.5.0 完全一致**（`[3]` 返回 `None`）。<br>🔴 **接了它就有一条硬前提：本段目标 latent 与锚同网格**。中途插 latent 放大（🔍 0.6.8）会让二采的目标分辨率变高 ⇒ 接上必炸（见 §🔍 潜空间分块放大 的接法第 2 条 / README §10.9）⇒ **只有原生域那一采接它**。<br>实测（0.3MP 受控）：缝处亮度阶跃 **0.0009 vs 单用 cond 桥 0.0097（10.8×）**；与第三方 `Motion-Context` 同条件比 **4/5 项胜出** |
| `ref_anchor_latent` / `ref_anchor_stage` / `ref_anchor_frames`（0.6.0） | — / `-1` / `5` | **全局外观锚**（走 `minimax_refs` 原生协议，近零噪声全程骑乘每一步 = attention sink）。<br>依据 **Diff-VF 的 Skip Residual Guidance**（把真实细节按当前噪声水平混入，既填细节又守运动）——refs 块是它的黑盒等价物 ⇒ **既防长程漂移，又可能治缝后糊闪**。<br>`ref_anchor_stage ≥ 0` 时自动读 `output/relay_kit/<run_id>/stage_<该值>` 当锚；`-1` = 关 |
| `anchor_latent` / `anchor_blend` | — / `1.0` | **色档纠偏锚**（0.5.0）：全局锚段（通常第 1 段）的 AV latent。接上后拷贝前缀的逐通道均值/方差被 Reinhard 矩匹配拉向锚段 ⇒ 每步钉回的就是已复位色档的上下文，本段新内容跟着回到全局色档。**纠偏只作用于被裁掉的钉住前缀，不碰上一段成片。** `anchor_blend` = 纠偏强度（1 全量对齐；锚段与本段有意的风格差异时调低；不接锚时无效） |

**续接裁重叠**

| 参数 | 默认 | 说明 |
|---|---|---|
| `images` | — | 本段解码后的全部画面（含头部重叠区） |
| `trim_frames` | 0 | 裁掉的**钉住区**帧数。**接桥的 `[2]` 输出（trim_frames）即可自动同步**，不要手填 |
| `fps` | 24.0 | 帧率，用于把帧数换算成音频采样点 |
| `audio` | — | 本段音频。接了才与画面同裁，否则会音画不同步 |
| `settle_frames` | **0** | **0（0.5.0 起默认）= 不裁沉降** —— 实测「裁沉降」才是缝处跳帧的源头（裁 0 帧跳 0.020「几乎无感」／裁 8 帧 0.044／裁 16 帧 0.055），留下的是清晰度渐变、人眼容忍度极高；`-1` = 自动量出切换点并裁掉（**治糊但会引入跳帧**）；`N` = 固定多裁 N 帧 |
| `diagnostics` | **False** | **只读观测总闸**（2026-09-25 新增，追加在 optional 末位）。默认关 ⇒ 不跑 🧪 DTW 代价（E3）／裁量→跳跃曲线／🧪 外观三元组+漂移曲线（E4，需填 `run_id`）。三路**都不参与任何裁量**（纯打印）⇒ 关掉**不改变任何帧/latent/音频**，只省 CPU（实测三路合计 **0.361 s/段** @0.796MP/90 帧）。⚠ **本地产线要常看这三行** ⇒ 跑批入口显式传 `True`（`l1_api` 的 903 构造处）；对外默认关。<br>⚠ `settle_frames=-1` 时的 `detect_settle` / `boundary_jump_ratio` / `observation_profile` 属**裁量链路**，**不受**本开关影响 |

**`[3]` 输出 `prev_tail`**（0.5.0 新增，追加在末位）：= 钉住区最后一帧 = **`images[pin-1]`**。
喂给 `🔗 续接后处理 Post` 的 `guide`，跨段项才有"缝的另一侧"可对齐。
⚠️ **它是否等于"上一段的末帧"，取决于走哪条桥**：**复合桥走 `[0]` latent 拷贝时**，前 `pin` 帧是**逐位拷贝**的上段尾
⇒ `prev_tail` **就是**上段末帧；**复合桥的 conditioning 钉帧路线（原 Latent 桥）**下前 `pin` 帧是**本段模型重画**的 ⇒ 只是个**近似**
（实测代理误差可达 0.006，比它要修的缝阶跃还大）。所以把 `guide` 当"精确参照"用之前，
先确认你走的是哪条钉法（只接 `[3]` conditioning、不接 `[0]` latent 时是近似）。

### 🔗 续接后处理 Post（0.5.0 新增）

| 参数 | 默认 | 说明 |
|---|---|---|
| `images` | — | **唯一必填**。接裁重叠的 `images`（裁后画面） |
| `guide` | — | 接裁重叠的 `prev_tail`（= 钉住区最后一帧 = 缝的另一侧）。**只有跨段两项需要它**；不接时那两项自动跳过。⚠️ **它是不是"上段末帧"取决于走哪条钉法**：复合桥走 `[0]` latent 拷贝时**是**；只接 `[3]` conditioning 钉帧路线时只是近似（见上节 `prev_tail` 的警告） |
| `match_prev` | 0 | **跨段统计匹配**：段头逐通道均值+标准差对齐 `guide`（Reinhard 式一阶+二阶矩）。**只对齐统计量、不复制姿态 ⇒ 无重影**。治成片缝上的亮度阶跃。⚠️ **实测建议：在 Latent 桥（cond）路线上保持 0**——该路线的缝本身已到 0.0007（可感阈值以下），而 `guide` 只是近似参照（见上节 `prev_tail` 的警告），对齐它会**把首帧推离真参照**（实测阶跃 0.0007 → 0.0039）；它真正的用武之地是**拷贝桥**（`prev_tail` 才是真参照） |
| `match_prev_frames` / `_gain_max` / `_offset_max` | 12 / 1.15 / 0.06 | 作用帧数（权重线性衰减到 0）／对比度增益护栏／偏移护栏 |
| `match_prev_stats_frames` | 1 | **统计量取几帧**——本条最容易写错。`1`（默认）= 只取**紧贴缝的那一帧**（与单帧 `guide` 同口径 ⇒ 修正量恰是"缝上的阶跃"，首帧被拉向 guide 而**不会越过**）；`0` = 旧口径（对整个作用区聚合）——段头**内部有亮度梯度**时会把首帧**推过** guide、缝上凭空多出一个阶跃（真渲染实测阶跃 ×12.6，**仅对照用**）；`>1` = 前 N 帧聚合 |
| `lowfreq_pull` / `_frames` / `_blur` | 0 / 12 / 64 | **低频残差传递**：只把段头**低频**色档对齐 `guide`。与 `match_prev` 的区别：本项只做低频**加性**（一阶）。⚠ 两者作用域重叠，建议二选一。<br>⚠ **`_blur` 的耗时 ∝ 核半径²**：默认 64 在 2.07MP/12 帧要 **22.1 s**（0.80MP 8.6 s）⇒ **高分辨率下建议降到 16–32**（实测 k=32 → 5.6 s · k=16 → 1.6 s · k=9 → 0.6 s）；缝点阶跃 32/64 = **0.0011 vs 0.0024**，差异很小 ⇒ 降档几乎无损 |
| `head_zone_frames` | 24 | **组 2+3 共用的作用帧数**（从裁后首帧起）：下面「直方图 / 白平衡 / 反卷积 / 段体高频迁移」四项都按它作用（强度各自线性衰减到 0）。⚠ **只管组 2/3** —— 组 4 的「糊区锐化」用 `settle_sharpen_frames` |
| `hist_match` / `wb_match` | 0 / 0 | **段内**对齐（基准 = 本段段体）：直方图分布 / 灰世界白平衡（作用帧数见 `head_zone_frames`）。<br>⚠ `hist_match` 在高分辨率下会**自动等间隔子采样**求分位（整帧像素超 `torch.quantile` 上限 2^24 时）—— **0.3MP 及以下不触发**（走精确分位），0.8MP 起触发，约 **2 s/段**且**与分辨率无关**（2MP/4MP 同级） |
| `deconv_strength` / `_radius` | 0 / 1.5 | 反卷积去模糊（Wiener），提升段头高频（作用帧数见 `head_zone_frames`） |
| `detail_borrow` / `_blur` | 0 / 9 | 段体高频迁移（把段头高频换成段体的结构）（作用帧数见 `head_zone_frames`） |
| `settle_sharpen` / `_frames` | 0 / 24 | 糊区锐化（unsharp，渐变）。**不裁、不动时间轴 ⇒ 不可能引入跳帧**。⚠ `_frames` 只管这一项 |
| `settle_auto` | 0 | **自适应糊区补偿（推荐替代上面的固定锐化）**：节点**当场量**每帧清晰度对段体基线的亏空（缝后第 2 帧最深、~15 帧爬回的爬升区），按亏空比例锐化——亏空越深补得越多；已达标的帧（含清晰的帧 0–1）与段体**逐位不动**。真实数据实测：SelfLift 快测档糊区最低 61% → 86%（strength=1.0）/ 99%（1.5）、锐度比 0.945 → 1.007/1.038、爬升 15 帧 → ~8 帧；官方链几乎无亏空 ⇒ 本项**正确地几乎不动**（无误伤）。⚠ 只能恢复对比度，救不回彻底丢失的细节 |
| `cross_seg_ack` | **False** | 🔴 **跨段两项的总闸**。不打勾（默认）⇒ `match_prev` / `lowfreq_pull` **不作用**（报告里说明原因）。**为什么默认关**：只接 `[3]` conditioning 钉帧路线时 `prev_tail` 只是**近似**（代理误差 0.006 > 要修的缝阶跃 0.0007），实测对齐它反而把缝阶跃**放大 ×12.6** ⇒ 默认不让用户踩这个坑。确认 `guide` 是真参照（**接了 `[0]` latent 拷贝的复合桥**）才打勾 |
| `baseline` | `robust` | **组 2/组 3 的段体参考怎么取**。`robust`（默认）= 取段体**逐帧亮度中央 50%** 的帧做统计，并报**离散度** `(p75−p25)/中位`；离散度 > 0.08 ⇒ 组 2/组 3 **自动弃权**（宁可不动，也不用不可靠基准改画面）。`legacy` = 0.5.0 旧口径（整段均值，不筛不弃权），**仅作对照复现** |

**全部默认 0 ⇒ 逐位直通**（不接线时行为与 0.4.x 一致）。执行顺序：跨段色调对齐 → 段内色调对齐 → 补高频 → 锐化收口。

### 🔗 续接音频缝（0.5.0 新增）

| 参数 | 默认 | 说明 |
|---|---|---|
| `audio` | — | **唯一必填**。接裁重叠的 `audio`（**第 1 段**没有裁重叠节点时，直接接音频解码 `VAEDecodeAudio`） |
| `run_id` / `stage_index` | `relay` / 0 | 与「续接桥 / Latent 存」**一字不差**；按段号顺序跑，别跳段 |
| `patch_seconds` | 0 | **头部补丁长度（秒）**。0 = 关（逐位直通）。要开先试 **0.2–1.2**：补丁区 = 上一段床声 + 电平对齐的渐入，盖住段首 priming 静默即可；过长会把本段自己的起拍/内容吃掉（实测 1.2s 曾把 BGM 起拍压平）。🛡 **0.6.5 起默认有台词守卫**：本段头部台词起点被自动探测，patch 收缩到台词前 0.40s（2×全源中位能量判据 + 持续帧；`patch_guard=0` 关闭）。⚠ 必须先在**第 1 段**就接本节点（第 2 段的床源是它落盘的音频） |
| `bed_select` | `tail` | 床声选窗：`tail` = **上一段尾部同长窗**（紧邻缝、电平/音色与缝前天然连续——实测比"取全局最静"好 29 dB）；`quiet` = 0.5.0 旧行为（带下限选最静），仅对照复现。补丁还会做**电平对齐**（对齐缝前电平，±6 dB 限幅 + 0.995 峰值护栏） |
| `patch_guard` | `True` | 🛡 **patch 台词守卫（默认开，0.6.5）**。开 = 自动探测本段头部台词起点，patch 收缩到台词前 0.40s；台词太靠前（< 0.10s 可用）则 patch 整个关闭、头部原样保留；头部纯环境声 ⇒ 与关闭逐位一致（零副作用）；BGM 素材不触发（BGM 峰 < 2×中位；首版 P10 基线被 S2 压力矩阵打回）。真渲染验证：台词 0.90s ⇒ 收缩后一字未损；台词第 0 帧起 ⇒ 零吞字。 |
| `tile_seconds` | 0 | 床环铺瓦片长（秒）。0 = 整窗直取；前段干净窗短于 N 时用 1.2 |
| `fade_seconds` | 0.25 | 补丁边界（第 N 秒处）的交叉淡变宽度。0 = 硬切 |
| `bed_stage` | 0 | 用**第几段**的音频当床源。⚠ 必须 **< 本段段号**（床源得是已渲染完的段） |
| `join_*`（5 个，全折叠） | 见 tooltip | **`[2]` 输出 `joined` 的拼接参数**：`join_curve`（等功率 `qsin`/线性 `tri`）、`join_prime_ms`（去编码器 priming）、`join_cross_ms`（交叉窗）、`join_segment_seconds`（每段音频有效时长 = 帧数/fps）、`join_align_seconds`（每缝画面裁量 = 裁帧数/fps）。`align>0` = **J-cut 时间轴守恒**：输出与裁后视频严格等长（实测对齐误差 0）、片尾无静音、跨段响度自动匹配（±6 dB 限幅）；`align=0` = 旧缩短语义（仅对照） |

**`[2]` 输出 `joined`**：把链上各段音频拼成**整片一条音轨**（本节点输出，供封装/成片直接用）——
编码器给每段 mp4 头带来的 ~33 ms priming 静音在此被剔除，段间交叉用等功率曲线（不相关内容下
比线性淡变高 ~3 dB），是"缝上瞬时卡顿"的节点层修法。另落盘 `audio_raw_*`（原始未裁音频 =
J-cut 前奏素材源）与 `audio_joined.safetensors`（整片一条）。

**落盘**：每段都会写 `output/relay_kit/<run_id>/audio_NNNNN.safetensors`（与 latent 同目录，
`audio_` 前缀互不覆盖）——**第 1 段也必须接本节点**，第 2 段的床源就是它。

**守卫**（都明确报错，不静默）：床源段号 ≥ 本段 → raise；床源文件不存在 → raise 并提示先跑第几段；
`patch_seconds` 超出段长 → **夹到段长−1 并告警**（不炸整条链：一个环境声补丁不值得中断 30 分钟的渲染）。

**硬约束**：`context_latent` 与本段必须**同分辨率、同通道数**。
latent 无法缩放，不一致只能让上一段重跑或从本段重启链 —— 会明确报错。

### 🔍 潜空间分块放大（0.6.8 新增）

**画质域 · latent 层**。上游是社区 MIT 节点 `MinimaxH3LatentUpscaler3D`（作者 `LBH-123-AI`），
本节点是它的 **AV 打包 latent 适配层**：拆包 → 逐块调放大 → 回包（**音频流原样带回**）。
性质（读上游源码核过）：**零去噪 / 零重采样**、`target_size=(t,H2,W2)` ⇒ **时间维一帧不动**
（帧网格、`裁重叠` 的 22 帧裁量、口型与钉住区逐位连续都不受影响）。

| 参数 | 默认 | 说明 |
|---|---|---|
| `model_name` | 下拉 | 权重来自 `models/latent_upscale_models/`（**直接沿用作者目录与作者的 `scan_models()`**，本包不另立目录、不复制第二份）。⚠️ 要的是 **H3 latent 放大权重**（24 通道专用），**不是** ESRGAN 那类像素模型 |
| `mode` | `scale by multiplier` | ① `scale by multiplier` = 给系数；② **`target dimensions` = 直填宽高（推荐：与 `ResolutionSelector` 对接，天然落在 32 的台阶上）**；③ `megapixels` = 给总像素 |
| `scale` | `2.0` | 【×倍数模式】只放大不缩小（<1 由上游报错）。⚠️ 非 `align` 台阶的系数（如 ×1.1）会**各轴分别收边 ⇒ 横竖不等比 + 长宽比漂移**，所以生产档建议改用 `target dimensions` |
| `width` / `height` | `1280` / `704` | 【目标尺寸模式】**像素**宽高，自动收边到 `align` 的倍数 |
| `megapixels` | `1.0` | 【兆像素模式】12GB 卡建议 ≤1.5，显存吃紧调小 |
| `chunks` | `1` | 【显存旋钮】沿时间维切几块。**1 = 整段一次过**（最快、最吃显存）。🔴 **`chunks>1` 会改画面**（实测 480×864/47 帧：逐像素 MAE **5.62/255**、192 帧里 0 帧逐位相同）—— 上游内部是 `AttnBlock3D` **体积注意力**，写死 32 帧一块，切块 = 换上下文，**不是"数学等价的省显存"**。所以：默认锁 1，只在显存真放不下时升，且**升完必须重看缝** |
| `overlap` | `5` | 块间两侧各留几帧做线性渐变混合。默认 5 = 上游 3D 时间核（`temporal_kernel`）；**不许大于模型的核宽**，且受下面的合规约束 |
| `align` | `32` | 输出宽高收边到的倍数。**32 是 H3 放大模型的硬要求，别改小** |
| `precision` | `bf16` | bf16/fp16 省显存；fp32 最稳但慢。与权重自身精度一致最保险 |
| `device` | `cuda` | `cpu` 档只用于排查，实际慢得多 |
| `force_unload` | False | 跑完把放大模型退回 CPU 腾显存。⚠ 分多块时会反复装卸（更慢），默认关 |

**合规约束（fail-closed）**：每块至少 `2·overlap+1` 帧 ⇒ `chunks ≤ T // (2·overlap+1)`。
超限**直接报错并给出最大合法块数**，绝不偷改参数（与掩码/帧网格同一纪律）。
拼接数学与上游同口径：两侧 replicate 填充 + 线性渐变权重 + 按累计权重归一。

**输出**：`[0] latent`（回包，音频流原样）、`[1] report`（请求块数→实际块数 / T / 音频形状 /
上游调用次数 / 显存峰值 / 耗时 —— 分块是否真按你要的走，看这个）。

**接法两条硬线**：
1. **续接契约取放大前**：`🔗 续接 Latent 存` 必须接在**一采输出**上（原生域），不能接本节点之后
   —— 否则下一段的桥拷到的是 SR 域数据、再过一次 SR = 双倍漂移。
2. **二采的 guider 不接桥的 `conditioning`**：钉帧锚（`minimax_keyframes`）与本段目标**必须同网格**，
   放大之后接上会在模型里炸 `shape mismatch [2392,96] vs [3134,96]`（机理见
   [`docs/01-mechanism.md`](01-mechanism.md)「🔍 放大之后：哪条线留在原生域」）。
   与上面 `context_latent` 的「同分辨率」硬约束是**同一族问题**：latent 侧那条会明确 raise，
   conditioning 侧这条炸在模型深处 —— 所以接线时就别接。
