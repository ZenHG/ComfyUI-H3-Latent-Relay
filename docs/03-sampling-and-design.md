# 采样链取舍与本包的设计取向

> 本文件由 README（0.6.0 梳理）拆出。
> 📐 **槽位记号**：本文一律 `[N]` = **0 起算**（UI 上第 N 个口 = `[N-1]`）。
> 搬运自旧稿的「第 N 路」是 1-based 的历史写法，已在关键处改为 `[N]`。
> 主 README 只留快速阅读必需的结论与指针。

---

## ✅ 默认够用 —— 先别调参

照上面三步跑完，就是这个包的**默认水平**：接缝起点干净、不跳帧、不重影，音频缝有上一段环境声打底。
**多数用户到此就够了。** 下面这些默认值**不是"待你优化的起点"，而是实测过的推荐值**：

| 旋钮 | 默认 | 为什么不建议动 |
|---|---|---|
| `trim_frames` | `22` | 钉住窗长度。实测**加长（22→39）不治糊、反而更差**（段头清晰度 0.864→0.805、缝处阶跃 0.0627→0.0732） |
| `settle_frames` | `0` | 不裁沉降。实测**裁沉降才是跳帧的来源**（裁 8 帧跳到 0.044、16 帧 0.055） |
| `seam_ghost` | `0` | 实测它只把一跳拆成两跳 |
| `mask_mode` | `hard` | 真续接。其余三档是**对照实验档**（见下） |
| Post 的画质旋钮 | 全 `0` | 全关 = **逐位直通**。它们是"补最后一点"，不是"必开" |
| 音频缝 `patch_seconds` | `0` | `0` = 直通；要用才开（且**第 1 段也要接** —— 它是后段的床源） |

> **🚫 实验档清单（别当默认）**：`mask_mode="taper"`（假拷贝，钉住区**没有被钉住**）、
> `mask_mode="ramp"`（copy 桥上实测与 `hard` **完全等同**：0.0407 vs 0.0402）、
> `mask_mode="blend"`、`match_prev=0.7`（实测把缝阶跃**放大 12.6 倍**）。
> 这些是留给我们自己做对照的，**产线默认一律不要开**。

**只有两种情况需要继续往下看**：

1. **画面细节/清晰度**不满意 → 先看下面「采样链」这一刀，再看「参数 → 续接后处理 Post」；
2. **缝上还剩极轻微的过渡**、想把最后 1% 也压掉 → 看「两条续接路线：怎么选」与「参数」。

### 🎛 采样链：两条路的取舍（通用说明，选哪条由你决定）

> 本包只处理 latent / AV 张量，**不含采样器**。下面不是"让你照抄我们的配置"，
> 而是**机制 + 实测**，帮你判断你自己那条链处在什么位置。

**先自查一件事**：打开你的采样器节点，看它是不是**渐进分辨率**（前期低分辨率、后期提升到全分辨率，
如 SelfLift 的 `transition_step` / `lowres_scale`），再看调度器**总步数** `N`。
如果是，那么**全分辨率上真正跑的步数 ≈ `N − transition_step`** —— 这个数就是细节的上限来源。
官方文档给的例子（8 步取 6）与你可能的默认（6 步取 4）**都只剩 2 步全分辨率**，这不是个别配置问题。

🔴 **续接链上还多一笔账（本包主场景独有，独立生成的链没有）**：渐进链靠 `latent` 里的
**噪声掩码**钉住缝区，而**低分辨前缀用的是降采样后的掩码 + 降采样后的锚**，真源只在全分辨相用。
⇒ **`transition_step` 同时是「细节旋钮」和「缝质量旋钮」**：调大它 = 更多步在糊化的掩码边界上钉帧。
把渐进链接进本包的桥之后，这条耦合才会出现 —— 别把它当成纯画质旋钮。

**为什么会"糊"（机制，不是调参失误）**：低分辨前缀的 latent **物理上没有高频**；
学习式提升只能"脑补"高频；剩下 2 步全分辨率远不足以补回来。
对比**全程全分辨率**的官方链（`SamplerCustomAdvanced` + euler），差别是**结构性的**。

**实测（同 seed、同提示词、同参考图、同参数；672×1184 / 90 帧 / 2 段；测法与复现见 `CHANGES.md`）**：

> ⚠️ **口径**（别当因果读）：两臂跑的是**各自节点的现用配置** —— 官方臂 =
> `SamplerCustomAdvanced` + euler（8 步 + Refiner），渐进臂 = UI 现值（`lowres_scale=0.5`、6 步 + Refiner 2）。
> 所以它证明的是**这两条现役配置谁细节高**，**不是**「渐进分辨率机制本身的天花板更低」。
> 剂量（`lowres_scale` / `transition_step`）是单调的，而**该机制的极限 = 低分辨前缀跑到全分辨率 = 官方链**。
> 想要「渐进链的天花板」这个数，得自己跑一组剂量扫描 —— 本包**未做**（见本节末的诚实标注）。

| | **渐进分辨率链（SelfLift 类）** | **全程全分辨率（官方 `SamplerCustomAdvanced` + euler）** |
|---|---|---|
| 续段**细节**（全局高频中位） | 0.005750 | **0.011345（1.97×）** |
| 续段 1:1 局部细节 | 0.00604 | **0.01682（2.78×）** |
| 缝处亮度阶跃 | 0.0123 | **0.0094** |
| 缝区低频连续比（→1 = 连续） | 0.76 | **0.98** |
| 音频缝 `min_local/median`（去 priming 后） | **0.909** | 0.332 |
| 每段 NFE（去噪评估次数） | 相等（渐进分辨率**不增加** NFE） | 相等 |
| CFG | 可调（如 1.1） | **恒 1**（`BasicGuider` 无 negative 槽） |

**什么时候保留渐进分辨率链**：显存或时间受限；需要它的专属能力（高低分辨双模型 / 时域稳定补丁）；
素材上**音频缝比画面细节更要紧**（上表实测该链音频缝更好）。
⚠️ 别把「切块省显存」算进它的专属能力：渐进采样器普遍用「分块注意力」实现高分辨率相，
而**分块与噪声掩码互斥**（掩码要逐步钉死，分块会把跨块的时间上下文切断）⇒
**只要本包的桥在场（= 有掩码），分块这条路就是关的**，显存旋钮只剩 `lowres_scale` 一个。
**什么时候换全程全分辨率**：**画面细节优先**、显存能撑住 —— 这是"接缝无感"最直接的一步。

**其实不止两条路 —— 本包自己就提供了第三条**（主 README §4.1「全流程档」把它接完了，8 个节点全在场）：

| | ① 全程全分辨率（单遍） | ② 渐进分辨率（单遍） | ③ 原生域一采 → 🔍 放大 → 高分辨二采（两遍） |
|---|---|---|---|
| 细节上限 | **最高**（每步都在目标网格） | 受 `N − transition_step` 限制 | **高**（二采每步都在目标网格） |
| 显存 / 时间 | 最贵 | **最省** | 中（一采在原生域、二采在高分辨率） |
| 钉帧（`conditioning` 侧） | ✅ 全程 | ⚠️ 过渡点换锚 | ✅ **一采全程**（二采侧**必须放开**，否则当场炸：主 README §10.9） |
| 缝区钉住（`latent` 掩码侧） | ✅ | ⚠️ 掩码边界随低分辨相降采样（本节开头那笔账） | ✅（一采侧） |
| 链外依赖 | — | 需第三方渐进采样器 | 需本包 `🔍 潜空间分块放大`（+ 作者的权重，见主 README §2.1） |
| 适合 | **画面细节优先** | 显存/时间受限，音频缝比画面更要紧 | 显存只够原生域、又不想接受渐进链的细节上限 |

**走两遍法时的关键纪律**（主 README §4.1 有完整 12 步）：放大属**交付支路，不进续接契约** ——
`Latent 存` 要接在放大**之前**，否则下一段拿到的就是放大过的 latent，再过一次放大 = 双倍漂移。

🔴 **② 和 ③ 只能选一个，别串联**：渐进采样器**内置**的那次提升（SelfLift 叫 `latent_upsample`）
与本包 `🔍 潜空间分块放大` **调用同一个第三方模型、同一份权重、做的是同一件事**
（都只吃 24 通道 H3 潜空间权重，都放在 `models/latent_upscale_models/`）。
两个都开 = 同一段 latent 被放大两次 ⇒ 漂移叠加。
判据：**同一条链里放大只该发生一次** —— 要么在采样器内部（②），要么作为独立节点夹在两遍之间（③）。

**若保留渐进分辨率，这几个参数决定细节与成本的分配**（参数名以 SelfLift 为例，同类实现语义相近）：

| 参数 | 作用 | 代价 |
|---|---|---|
| `transition_step` | 低分辨前缀的**步数**（= 便宜的步）；全分辨步数 = `总步数 − 它`。**降它 ⇒ 同样 NFE 下全分辨率占更多**。合法区间 `1 … 总步数−2`，越界直接 raise（不吸附） | 全分辨步更贵（时间 ↑）。🔴 **在续接链上它还是缝质量旋钮**（见本节开头那笔账） |
| `lowres_scale` | 低分辨前缀的**空间比例**（越大越细），合法区间 `0.25–1.0`。**`1.0` 就等于全程全分辨率 = 官方链** —— 加速收益归零，只剩两段调度的额外开销 | 算力 ↑ |
| `rho` | `>0` 开启**锚点修正**（把高风险位置朝像素 VAE 锚点拉，治提升伪影）。⚠️ **它不是「修正强度」，是「被修正的位置比例」**：实现上取误差图的高分位阈值，只修最不一致的那 `rho` 比例（`0.6` = 修最差的 60%），强度由下面两个参数给。官方 README 给 H3 的建议起点 `rho=0.6`、`w_min=w_max=1`。**本项目此前为 0，即该能力从未启用** | 多一次 VAE 解码→上采样→重编码往返。🔴 **`rho=1.0` 不能配噪声掩码**（纯锚点路线在掩码在场时取到空张量 ⇒ `TypeError: unsupported operand type(s) for -: 'Tensor' and 'NoneType'`） |
| `w_min` / `w_max` | 修正**强度**的下界 / 上界（在选中的位置内按误差归一） | — |
| 分块（`highres_tiling` 一类） | 高分辨率相切块算，省显存 | 🔴 **与噪声掩码互斥** ⇒ 续接链上不可用（见上） |
| 内置提升器（`latent_upsample` 一类） | 用学习式提升器替掉双线性插值 | 与本包 `🔍` 同源，**二选一**（见上） |

> ⚠️ **诚实标注（分两层，别混读）**：
> - ✅ **已核（源码级 + 纯 CPU 复现，零 GPU）**：上表的语义纠偏（`rho` = 位置比例而非强度）、
>   `transition_step` 的缝耦合、`rho=1.0` + 掩码的崩、分块与掩码互斥、内置提升器与本包 `🔍` 同源。
> - ❌ **未测（画质）**：`rho` / `w_min` / `w_max` / `transition_step` 对**成片画质与音频缝的实际影响**，
>   本包**没有跑过剂量扫描**。上面那张实测表只回答了「两条现役配置谁高」，
>   **没有**回答「渐进机制的天花板在哪」。测出来会写进 `CHANGES.md`，不吹不藏。

### 🧭 本包的设计取向：**该量的不让用户配，接缝无感是目标**

- **能智能量出来的，就不给旋钮**：裁多少帧由节点**当场测**（`trim_frames` 是"不许你配"的那一类）、
  沉降检测、音频床声窗位、电平对齐，都是运行时从你这段画面/音频里量出来的 ——
  因为这些是**客观可测量**的（见「裁多少帧：不让你配，由节点当场量」）。
- **只有"偏好 / 硬件"类才交给你**：镜像哪条链、要不要开画质域修复、掩码档位 ——
  这些取决于你的显存、素材与审美，**没有客观最优**，所以本包把它们放上画布并给推荐默认。
- **默认档就是"无感"档**：照「5 分钟跑通」跑，接缝处应当**看不出来**；
  还看得出来时，按上一节的顺序（先链、后画质域修复、最后掩码/裁量）逐级排查。
